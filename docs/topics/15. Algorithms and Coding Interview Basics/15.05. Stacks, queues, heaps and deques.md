# 15.05. Stacks, queues, heaps and deques

---

<a id="alg-linear-001"></a>

<details>
<summary><strong>ALG-LINEAR-001. When would you use a stack in a coding task?</strong></summary>

#### Short answer

Use a stack when the most recent unfinished item must be processed first.

#### Interview answer

A stack fits LIFO problems: parsing parentheses, evaluating expressions, undo-like behavior, DFS, backtracking and matching nested structures. In Java, I normally use `ArrayDeque` as a stack with `push`, `pop` and `peek`.

The core signal is nested or last-open-first-closed behavior.

#### Deep dive

Stacks can also replace recursion explicitly when recursion depth is risky or when I need more control over state.

#### Production angle

Parsing, validation, workflow rollback and tree/graph traversal may use stack-like state.

#### Traps / caveats

- Prefer `ArrayDeque` over legacy `Stack`.
- Handle empty stack before popping.
- Be careful with recursion depth if using call stack.

#### Optional Anki

Q: What behavior does a stack model?
A: Last-in, first-out.

</details>

<details>
<summary><strong>ALG-LINEAR-002. How would you solve valid-parentheses style problems?</strong></summary>

#### Short answer

Push opening brackets; for each closing bracket, pop and verify it matches.

#### Interview answer

I scan left to right. If I see an opening bracket, push it. If I see a closing bracket, the stack must not be empty and the top must be the matching opener. At the end, the stack must be empty.

This is `O(n)` time and `O(n)` space in the worst case.

#### Deep dive

A map from closing to opening bracket keeps the logic clean. For only one bracket type, a counter may be enough.

#### Production angle

The pattern generalizes to nested validation: tags, expressions, scopes and structured config.

#### Traps / caveats

- A closing bracket with empty stack is invalid.
- Leftover open brackets are invalid.
- Mixed bracket types need exact matching.

#### Optional Anki

Q: Valid-parentheses final stack state?
A: Empty.

</details>

<a id="alg-linear-003"></a>

<details>
<summary><strong>ALG-LINEAR-003. Why is `ArrayDeque` usually preferred over `Stack` in Java?</strong></summary>

#### Short answer

`ArrayDeque` is modern, faster for local stack use, and avoids legacy `Vector` behavior.

#### Interview answer

`Stack` is an old class that extends `Vector`, so it carries synchronized list-style operations that do not model a clean stack abstraction. `ArrayDeque` implements `Deque`, has efficient operations at both ends and is the usual choice for local LIFO or FIFO algorithms.

Use `push`, `pop`, `peek` for stack semantics.

#### Deep dive

`ArrayDeque` does not allow null elements, which is usually good because null would make `poll`/`peek` ambiguous.

#### Production angle

Choosing modern collection APIs improves clarity and performance in parsing, traversal and request-local algorithms.

#### Traps / caveats

- `ArrayDeque` is not thread-safe.
- It rejects null elements.
- For cross-thread handoff, use a concurrent or blocking queue.

#### Optional Anki

Q: Preferred Java stack implementation for local algorithms?
A: `ArrayDeque`.

</details>

<a id="alg-linear-004"></a>

<details>
<summary><strong>ALG-LINEAR-004. How is a queue used in BFS?</strong></summary>

#### Short answer

BFS uses a queue to process nodes in discovery order, level by level.

#### Interview answer

Start by adding the source node to a queue and marking it visited. While the queue is not empty, remove the next node, process it, and enqueue unvisited neighbors. Because nodes are processed in FIFO order, BFS explores all nodes at distance `d` before distance `d + 1`.

This is why BFS finds shortest paths in unweighted graphs.

#### Deep dive

For grid BFS, neighbors are usually up, down, left and right, with bounds checks and a visited matrix.

#### Production angle

BFS-like traversal appears in dependency exploration, reachability checks and workflow expansion.

#### Traps / caveats

- Mark visited when enqueueing to avoid duplicates.
- BFS can consume large memory on wide graphs.
- Weighted shortest paths need a different algorithm.

#### Optional Anki

Q: Why does BFS find shortest path in unweighted graphs?
A: It processes nodes by increasing distance.

</details>

<a id="alg-linear-005"></a>

<details>
<summary><strong>ALG-LINEAR-005. What is a heap, and how is it exposed through `PriorityQueue` in Java?</strong></summary>

#### Short answer

A heap is a structure that can repeatedly return the minimum or maximum priority element efficiently.

#### Interview answer

Java's `PriorityQueue` is commonly backed by a binary heap. By default it removes the smallest element according to natural ordering. With a comparator, it can represent custom priorities or a max-heap style order.

Offer and poll are `O(log n)`, peek is `O(1)`.

#### Deep dive

`PriorityQueue` does not keep iteration order sorted. Only repeated `poll()` returns elements by priority.

#### Production angle

Priority queues are useful for scheduling, retries, top-K selection and merging sorted streams.

#### Traps / caveats

- No null elements.
- Mutating priority fields after insertion breaks ordering.
- Iteration is not sorted.

#### Optional Anki

Q: `PriorityQueue.poll()` complexity?
A: `O(log n)`.

</details>

<a id="alg-linear-006"></a>

<details>
<summary><strong>ALG-LINEAR-006. How do heaps help solve top-K problems?</strong></summary>

#### Short answer

Maintain a heap of size `k` so you do not sort all elements.

#### Interview answer

To find top `k` largest elements, keep a min-heap of size `k`. For each item, add it if the heap has room. Otherwise compare it with the heap root; if it is larger, replace the root. At the end, the heap contains the top `k`.

This is `O(n log k)` instead of sorting all `n` elements in `O(n log n)`.

#### Deep dive

If `k` is close to `n`, sorting may be simpler and competitive.

#### Production angle

Top-K appears in leaderboards, reports, search results, monitoring and sampling.

#### Traps / caveats

- Pick min-heap vs max-heap correctly.
- Define tie-breaking.
- The heap output itself may need final sorting.

#### Optional Anki

Q: Top K largest usually uses what heap?
A: A min-heap of size K.

</details>

<a id="alg-linear-007"></a>

<details>
<summary><strong>ALG-LINEAR-007. What comparator pitfalls can break `PriorityQueue` solutions?</strong></summary>

#### Short answer

Broken comparators, mutable priority fields, missing tie-breakers and overflow can all break priority behavior.

#### Interview answer

The comparator must define a stable, transitive ordering. Avoid subtraction like `b - a` for max-heap behavior because it can overflow. If two items have equal priority but deterministic output matters, add a tie-breaker. Do not mutate fields used by the comparator while the object is inside the queue.

#### Deep dive

`PriorityQueue` does not automatically reorder an element when its priority changes. Remove and reinsert if priority updates are needed.

#### Production angle

Priority bugs can delay retries, process work in the wrong order or make tests flaky.

#### Traps / caveats

- Iterating the queue is not sorted.
- Comparator equality can make order nondeterministic.
- Null priorities need explicit handling.

#### Optional Anki

Q: Does `PriorityQueue` reheapify after item mutation?
A: No.

</details>

<details>
<summary><strong>🧠 ALG-LINEAR-008. What is a monotonic stack, and what problems does it solve?</strong></summary>

#### Short answer

A monotonic stack keeps elements in increasing or decreasing order to find nearest greater or smaller elements efficiently.

#### Interview answer

While scanning, remove stack elements that can no longer be the answer, then use the remaining top as the nearest useful candidate. This solves problems like next greater element, daily temperatures and largest rectangle in histogram.

Each element is pushed and popped at most once, so the scan is `O(n)`.

#### Deep dive

The hard part is deciding whether the stack should be increasing or decreasing and whether equality should pop.

#### Production angle

It is more of an interview pattern than a common backend tool, but it trains linear-time state reduction.

#### Traps / caveats

- Equality handling changes answers.
- Store indexes when distance or width matters.
- It is easy to reverse greater/smaller logic.

#### Optional Anki

Q: Why is monotonic stack often `O(n)`?
A: Each element is pushed and popped at most once.

</details>
