# 15.04. Sorting, binary search, intervals and greedy choices

---

<a id="alg-sort-001"></a>

<details>
<summary><strong>ALG-SORT-001. When is sorting a useful first step in a coding problem?</strong></summary>

#### Short answer

Sorting is useful when order exposes structure: adjacency, grouping, monotonic search or greedy choices.

#### Interview answer

Sorting can turn a hard problem into a scan. After sorting, duplicates become adjacent, intervals can be merged, two pointers become possible, and greedy choices can often be made in order.

The trade-off is `O(n log n)` time and possible loss of original order or indexes.

#### Deep dive

Sorting is not automatically optimal. If a hash map solves the task in `O(n)` without needing order, sorting may be unnecessary.

#### Production angle

Sorting large data in application memory can be expensive. For database-backed data, sorting may belong in SQL with indexes and limits.

#### Traps / caveats

- Sorting mutates lists/arrays unless copied.
- Original indexes may be needed.
- Comparator bugs can break results.

#### Optional Anki

Q: What does sorting often make visible?
A: Adjacent duplicates, order and monotonic structure.

</details>

<a id="alg-sort-002"></a>

<details>
<summary><strong>ALG-SORT-002. How do you write a correct comparator in Java?</strong></summary>

#### Short answer

Use `Comparator.comparing`, `thenComparing`, explicit null handling and safe numeric comparison.

#### Interview answer

A comparator must be consistent and transitive. I avoid `a - b` because it can overflow, and use `Integer.compare`, `Long.compare` or comparator helpers. I define null ordering if nulls are possible and add tie-breakers when deterministic order matters.

For example: `Comparator.comparingInt(User::age).thenComparing(User::id)`.

#### Deep dive

Comparator equality affects `TreeSet` and `TreeMap` uniqueness. If `compare(a, b) == 0`, those collections treat keys as the same even if `equals()` says otherwise.

#### Production angle

Comparator bugs cause unstable pagination, missing report rows and inconsistent API responses.

#### Traps / caveats

- Do not subtract for comparison.
- Do not depend on mutable fields.
- Add tie-breakers for stable ordering.

#### Optional Anki

Q: Why avoid `a - b` in comparators?
A: It can overflow and violate comparator rules.

</details>

<a id="alg-sort-003"></a>

<details>
<summary><strong>ALG-SORT-003. When is binary search applicable?</strong></summary>

#### Short answer

Binary search applies when the search space is sorted or the predicate is monotonic.

#### Interview answer

The classic case is finding a value in a sorted array. More generally, binary search works when I can ask a yes/no question where answers switch only once, such as "is this capacity enough?" or "is this time feasible?"

The invariant is that the answer remains inside the current range.

#### Deep dive

Binary search can search over indexes, values, answer space or time, but only with a monotonic condition.

#### Production angle

Binary search thinking is useful for tuning thresholds, finding regressions and searching ordered logs or versions.

#### Traps / caveats

- The data or predicate must be monotonic.
- Boundary conventions must be consistent.
- Duplicate values require first/last occurrence logic.

#### Optional Anki

Q: Binary search needs what property?
A: Sorted order or a monotonic predicate.

</details>

<a id="alg-sort-004"></a>

<details>
<summary><strong>ALG-SORT-004. How do you find the first or last occurrence with binary search?</strong></summary>

#### Short answer

Continue searching after a match, tightening toward the desired boundary.

#### Interview answer

For first occurrence, when `mid` matches, record it and move `right` left to see if an earlier match exists. For last occurrence, record it and move `left` right. The loop invariant should keep the possible boundary inside the search range.

Another style is lower-bound and upper-bound: first index `>= target`, first index `> target`.

#### Deep dive

Lower-bound templates often reduce off-by-one bugs because they use half-open ranges like `[lo, hi)`.

#### Production angle

Boundary searches appear in time-series data, sorted events, pagination cursors and version ranges.

#### Traps / caveats

- Returning any match is not enough.
- Duplicates require boundary logic.
- Verify empty and all-equal arrays.

#### Optional Anki

Q: Lower bound finds what?
A: First position where value is greater than or equal to target.

</details>

<a id="alg-sort-005"></a>

<details>
<summary><strong>ALG-SORT-005. How do you avoid infinite loops and overflow in binary search?</strong></summary>

#### Short answer

Use safe midpoint calculation, consistent boundaries and guaranteed progress.

#### Interview answer

Compute `mid` as `left + (right - left) / 2`, not `(left + right) / 2`, to avoid overflow. Choose either inclusive `[left, right]` or half-open `[left, right)` boundaries and stick to it. Each branch must move `left` or `right` so the range shrinks.

Then test empty, one element, first, last and missing values.

#### Deep dive

Half-open loops often look like `while (left < right)`, with updates `right = mid` or `left = mid + 1`.

#### Production angle

Overflow bugs in indexes and sizes can become security or availability issues when input is large.

#### Traps / caveats

- `mid = (l + r) / 2` can overflow.
- `left = mid` may not progress.
- Mixing boundary styles causes off-by-one bugs.

#### Optional Anki

Q: Safe binary search midpoint?
A: `left + (right - left) / 2`.

</details>

<a id="alg-sort-006"></a>

<details>
<summary><strong>🧠 ALG-SORT-006. How do you search in a rotated sorted array at a high level?</strong></summary>

#### Short answer

Use binary search by identifying which half is sorted at each step.

#### Interview answer

In a rotated sorted array, one side of `mid` is usually sorted. If the left half is sorted, check whether the target lies between `left` and `mid`; if yes, search left, otherwise right. If the right half is sorted, do the symmetric check.

The key is using sorted-half membership to discard half the array.

#### Deep dive

Duplicates make this harder because equality can hide which half is sorted. Some variants degrade toward `O(n)`.

#### Production angle

This is mainly a coding-interview pattern, but it tests whether binary search is understood beyond exact sorted arrays.

#### Traps / caveats

- Duplicates change the problem.
- Boundaries are easy to invert.
- It is not a common backend production algorithm.

#### Optional Anki

Q: Main trick in rotated-array search?
A: Identify the sorted half and decide whether target is inside it.

</details>

<a id="alg-sort-007"></a>

<details>
<summary><strong>ALG-SORT-007. How do you merge overlapping intervals?</strong></summary>

#### Short answer

Sort by start, then scan and merge with the current interval when ranges overlap.

#### Interview answer

First sort intervals by start. Keep a current interval. For each next interval, if its start is less than or equal to the current end, merge by extending the end. Otherwise, output the current interval and start a new one.

This is `O(n log n)` from sorting and `O(n)` scan after that.

#### Deep dive

Define whether touching intervals overlap: `[1,3]` and `[3,5]` may or may not merge depending on inclusive/exclusive semantics.

#### Production angle

Interval merging appears in schedules, booking systems, time ranges, retention windows and deployment blackout periods.

#### Traps / caveats

- Define inclusive vs exclusive ends.
- Sort before scanning.
- Preserve or copy intervals deliberately.

#### Optional Anki

Q: First step for merging intervals?
A: Sort by interval start.

</details>

<a id="alg-sort-008"></a>

<details>
<summary><strong>🧠 ALG-SORT-008. How do you validate that a greedy choice is safe?</strong></summary>

#### Short answer

Show that making the local choice cannot make the optimal global solution worse.

#### Interview answer

A greedy algorithm repeatedly takes the locally best option. To justify it, I need an exchange argument or invariant: if an optimal solution does not use my greedy choice, I can swap it in without making the solution worse.

For interval scheduling, choosing the earliest finishing interval is safe because it leaves maximum room for future intervals.

#### Deep dive

If a local choice can block a better future choice, greedy is unsafe and DP or search may be needed.

#### Production angle

Greedy heuristics are common in scheduling, routing and prioritization, but they need clear constraints and metrics.

#### Traps / caveats

- A successful sample run does not prove greediness.
- Greedy can fail with negative weights or hidden constraints.
- Sorting criterion must match the proof.

#### Optional Anki

Q: What is an exchange argument?
A: A proof that replacing part of an optimal solution with the greedy choice does not hurt.

</details>
