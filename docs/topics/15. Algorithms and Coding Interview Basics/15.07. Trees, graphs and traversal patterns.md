# 15.07. Trees, graphs and traversal patterns

---

<a id="alg-tree-001"></a>

<details>
<summary><strong>ALG-TREE-001. What tree traversal patterns should a backend engineer know?</strong></summary>

#### Short answer

Know DFS, BFS and the main binary-tree orders: preorder, inorder and postorder.

#### Interview answer

Tree traversal means visiting each node in a deliberate order. DFS can be recursive or stack-based. BFS uses a queue and visits level by level. For binary trees, preorder visits node-left-right, inorder visits left-node-right, and postorder visits left-right-node.

The order should match what the problem needs.

#### Deep dive

Tree traversal is also useful for hierarchical domains: categories, comments, org charts, dependency trees and file trees.

#### Production angle

Traversal code must handle depth limits, cycles in invalid data and large hierarchies safely.

#### Traps / caveats

- Real backend "trees" may actually contain cycles.
- Recursion depth can be dangerous.
- Order must be deterministic if exposed by API.

#### Optional Anki

Q: BFS uses what data structure?
A: A queue.

</details>

<a id="alg-tree-002"></a>

<details>
<summary><strong>ALG-TREE-002. What is the difference between preorder, inorder and postorder traversal?</strong></summary>

#### Short answer

They differ by when the current node is processed relative to its children.

#### Interview answer

Preorder processes the current node before children, so it is useful for copying or serializing structure. Inorder processes left, current, right, and for a valid BST it visits values in sorted order. Postorder processes children before the current node, useful for deletion, cleanup or computing values from children.

#### Deep dive

These names are mainly for binary trees. General trees still have pre-order and post-order ideas.

#### Production angle

Postorder is useful for dependency cleanup: process dependents before parent.

#### Traps / caveats

- Inorder is only naturally sorted for BSTs.
- Recursive traversal can overflow on deep trees.
- Null child handling must be explicit.

#### Optional Anki

Q: Which binary-tree traversal sorts a BST?
A: Inorder.

</details>

<a id="alg-tree-003"></a>

<details>
<summary><strong>ALG-TREE-003. How does level-order traversal work?</strong></summary>

#### Short answer

Level-order traversal is BFS over a tree using a queue.

#### Interview answer

Start with the root in a queue. While the queue is not empty, remove a node, process it, and enqueue its children. To group by level, process the current queue size as one level before moving to the next.

This visits nodes from top to bottom and left to right if children are enqueued left first.

#### Deep dive

For level averages, right-side view or minimum depth, BFS is usually simpler than DFS.

#### Production angle

Level-order thinking appears in breadth-limited traversal of category trees, permission inheritance or dependency expansion.

#### Traps / caveats

- Queue size can grow large for wide trees.
- Handle null root.
- Enqueue children in deterministic order.

#### Optional Anki

Q: How do you separate BFS tree levels?
A: Capture queue size at the start of each level.

</details>

<a id="alg-tree-004"></a>

<details>
<summary><strong>ALG-TREE-004. How do you compute maximum depth or height of a binary tree?</strong></summary>

#### Short answer

Recursively compute `1 + max(leftDepth, rightDepth)`, with null depth as zero.

#### Interview answer

The recursive solution is natural: if the node is null, depth is `0`; otherwise depth is one plus the maximum depth of the children. BFS can also compute depth level by level.

Both visit each node once, so time is `O(n)`.

#### Deep dive

Recursive space is `O(h)`, where `h` is tree height. In the worst case of a skewed tree, that is `O(n)`.

#### Production angle

Deep hierarchies can break recursive code. Backend services should set depth limits or use iterative traversal for untrusted data.

#### Traps / caveats

- Define whether empty tree depth is 0 or -1.
- Skewed trees can overflow the call stack.
- Height and depth terminology can vary.

#### Optional Anki

Q: Recursive max-depth formula?
A: `1 + max(leftDepth, rightDepth)`.

</details>

<a id="alg-tree-005"></a>

<details>
<summary><strong>ALG-TREE-005. What invariant makes a binary search tree useful?</strong></summary>

#### Short answer

For each node, values in the left subtree are smaller and values in the right subtree are larger according to the ordering rule.

#### Interview answer

A BST is useful because the ordering invariant lets search, insert and delete move left or right instead of scanning every node. In a balanced BST, those operations are `O(log n)`. In a badly skewed tree, they can become `O(n)`.

Duplicates need a defined policy.

#### Deep dive

The invariant applies to entire subtrees, not only direct children.

#### Production angle

Java's `TreeMap` and `TreeSet` expose ordered tree-like behavior, but comparator correctness defines the ordering.

#### Traps / caveats

- A BST is not automatically balanced.
- Duplicates need a rule.
- Comparator inconsistency can break logical uniqueness.

#### Optional Anki

Q: BST invariant applies to what?
A: Entire left and right subtrees.

</details>

<a id="alg-tree-006"></a>

<details>
<summary><strong>ALG-TREE-006. How do you validate a binary search tree correctly?</strong></summary>

#### Short answer

Pass lower and upper bounds down the tree, not just compare each node with its parent.

#### Interview answer

For each node, verify its value is within the allowed range. The left child must be less than the current node and also respect all ancestor bounds. The right child must be greater and respect ancestor bounds. Then recurse with tightened bounds.

This catches violations deep in a subtree.

#### Deep dive

Use nullable bounds or wider types to avoid overflow around `Integer.MIN_VALUE` and `Integer.MAX_VALUE`.

#### Production angle

The same pattern validates hierarchical constraints where descendants must respect inherited limits.

#### Traps / caveats

- Parent-only checks are insufficient.
- Duplicates must match the chosen BST rule.
- Bounds can overflow if adjusted by `+1` or `-1`.

#### Optional Anki

Q: Correct BST validation tracks what?
A: Allowed min/max bounds from ancestors.

</details>

<a id="alg-tree-007"></a>

<details>
<summary><strong>🧠 ALG-TREE-007. What recursion-depth risks exist in tree algorithms?</strong></summary>

#### Short answer

Deep or skewed trees can cause `StackOverflowError` in recursive traversal.

#### Interview answer

Recursive tree code uses one stack frame per level. Balanced trees have height `O(log n)`, but skewed trees can have height `O(n)`. If input is large or untrusted, recursion may fail even when the algorithm is logically `O(n)`.

An iterative stack or queue is safer for very deep structures.

#### Deep dive

Java does not guarantee tail-call optimization, so tail recursion is not a general fix.

#### Production angle

This matters for category hierarchies, JSON trees, expression trees and dependency graphs from user or database data.

#### Traps / caveats

- Test balanced and skewed inputs.
- Do not assume tree data is valid.
- Add depth limits where appropriate.

#### Optional Anki

Q: Java recursive traversal risk?
A: `StackOverflowError` on deep trees.

</details>

<a id="alg-graph-001"></a>

<details>
<summary><strong>ALG-GRAPH-001. When should a problem be modeled as a graph?</strong></summary>

#### Short answer

Use a graph when entities are connected by relationships and traversal or reachability matters.

#### Interview answer

If the problem asks about dependencies, paths, connectivity, ordering, cycles or relationships between arbitrary objects, a graph model may fit. Nodes represent entities and edges represent relationships. Edges can be directed or undirected, weighted or unweighted.

The model should match the question being asked.

#### Deep dive

Graphs can be represented as adjacency lists, adjacency maps or matrices. For sparse backend-style data, adjacency lists are common.

#### Production angle

Graphs appear in dependencies, permissions, workflows, service calls, recommendation links and organization structures.

#### Traps / caveats

- Trees are special graphs.
- Real data may contain cycles.
- Graph size can explode quickly.

#### Optional Anki

Q: Common graph signal in a problem?
A: Reachability, dependencies, paths or cycles.

</details>

<a id="alg-graph-002"></a>

<details>
<summary><strong>ALG-GRAPH-002. What is the difference between BFS and DFS?</strong></summary>

#### Short answer

BFS explores level by level with a queue; DFS explores deeply with recursion or a stack.

#### Interview answer

BFS is good for shortest paths in unweighted graphs and level-order traversal. DFS is good for exploring connected components, cycle detection, topological sorting and backtracking-style traversal.

Both usually run in `O(V + E)` for adjacency-list graphs.

#### Deep dive

BFS often uses more memory for wide graphs. DFS can risk stack overflow if implemented recursively on deep graphs.

#### Production angle

Choosing traversal affects memory, latency and failure modes when traversing large dependency or permission graphs.

#### Traps / caveats

- BFS is not shortest path for weighted graphs.
- DFS recursion can overflow.
- Both need visited tracking for cyclic graphs.

#### Optional Anki

Q: BFS data structure?
A: Queue.

</details>

<a id="alg-graph-003"></a>

<details>
<summary><strong>ALG-GRAPH-003. How do you avoid revisiting nodes in graph traversal?</strong></summary>

#### Short answer

Keep a visited set or state map and mark nodes at the right time.

#### Interview answer

For BFS or DFS, store visited node IDs in a `Set`. In BFS, mark a node when enqueueing it, not when dequeuing, to avoid enqueueing it many times. For DFS cycle detection, use states like unvisited, visiting and visited.

The visited key should be a stable identifier, not a mutable object.

#### Deep dive

For grids, a boolean matrix can replace a set. For large graphs, visited memory may be significant.

#### Production angle

Visited tracking prevents infinite loops in dependency graphs, authorization graphs and hierarchical data with bad edges.

#### Traps / caveats

- Use stable IDs.
- Marking too late creates duplicate work.
- Different traversal roots may share visited state intentionally or not.

#### Optional Anki

Q: When should BFS usually mark visited?
A: When enqueueing.

</details>

<a id="alg-graph-004"></a>

<details>
<summary><strong>ALG-GRAPH-004. How do you find connected components in a graph?</strong></summary>

#### Short answer

Run BFS or DFS from every unvisited node and collect each traversal as one component.

#### Interview answer

Initialize an empty visited set. Iterate over all nodes. When a node is not visited, start BFS or DFS from it and mark all reachable nodes. That reachable group is one connected component. Repeat until all nodes are visited.

For an undirected graph, components are groups where every node is reachable from every other through some path.

#### Deep dive

For directed graphs, "connected" has variants: weakly connected and strongly connected. Clarify which is required.

#### Production angle

Components can identify isolated dependency groups, disconnected workflows or clusters of related records.

#### Traps / caveats

- Include isolated nodes.
- Directed graphs need clarification.
- Build adjacency correctly from edges.

#### Optional Anki

Q: How many DFS/BFS starts for components?
A: One per unvisited component root.

</details>

<a id="alg-graph-005"></a>

<details>
<summary><strong>ALG-GRAPH-005. How do you find a shortest path in an unweighted graph?</strong></summary>

#### Short answer

Use BFS and track distance or parent pointers from the source.

#### Interview answer

BFS explores nodes in increasing edge distance. Start from the source with distance `0`, then assign each unvisited neighbor distance `current + 1`. The first time a node is reached is its shortest distance in an unweighted graph.

To reconstruct the path, store each node's parent.

#### Deep dive

For multiple sources, enqueue all sources at distance `0`.

#### Production angle

Unweighted shortest path can model minimum hops in dependencies, transitions or simple routing.

#### Traps / caveats

- Weighted graphs need Dijkstra or another algorithm.
- Mark visited when enqueueing.
- Parent tracking is needed for the actual path, not just distance.

#### Optional Anki

Q: Shortest path in unweighted graph?
A: BFS.

</details>

<a id="alg-graph-006"></a>

<details>
<summary><strong>ALG-GRAPH-006. How do island-counting problems on a grid work?</strong></summary>

#### Short answer

Treat each cell as a graph node and run BFS or DFS from each unvisited land cell.

#### Interview answer

Scan the grid. When you find an unvisited land cell, increment the island count and traverse all connected land cells using BFS or DFS. Mark them visited so they are not counted again. Neighbors are usually four-directional unless the problem says diagonals count.

Time is `O(rows * cols)`.

#### Deep dive

You can mark visited in a separate matrix or mutate the grid if allowed.

#### Production angle

Grid traversal is an interview stand-in for connected-region detection and flood-fill style processing.

#### Traps / caveats

- Clarify diagonal connectivity.
- Check bounds before accessing cells.
- Avoid recursion on huge grids if depth is high.

#### Optional Anki

Q: Island-counting traversal?
A: BFS or DFS over neighboring land cells.

</details>

<a id="alg-graph-007"></a>

<details>
<summary><strong>ALG-GRAPH-007. What is topological sorting, and when is it useful?</strong></summary>

#### Short answer

Topological sorting orders directed acyclic graph nodes so dependencies come before dependents.

#### Interview answer

If tasks have dependencies, topological sort gives a valid execution order. Kahn's algorithm uses in-degrees: enqueue nodes with in-degree zero, remove them, and reduce neighbors' in-degrees. If not all nodes are processed, there is a cycle.

DFS can also produce topological order by adding nodes after visiting descendants.

#### Deep dive

Topological sort only works on directed acyclic graphs.

#### Production angle

It appears in build systems, migration ordering, job scheduling, workflow steps and dependency resolution.

#### Traps / caveats

- Cycles make ordering impossible.
- Multiple valid orders can exist.
- Direction of edges must be consistent.

#### Optional Anki

Q: Topological sort requires what graph type?
A: Directed acyclic graph.

</details>

<a id="alg-graph-008"></a>

<details>
<summary><strong>🧠 ALG-GRAPH-008. When is Dijkstra's algorithm useful, and what assumptions does it require?</strong></summary>

#### Short answer

Dijkstra finds shortest paths in graphs with non-negative edge weights.

#### Interview answer

Use Dijkstra when edges have costs and all costs are non-negative. Keep a priority queue of the best known distance to each node. Repeatedly process the node with the smallest distance and relax its outgoing edges.

With an adjacency list and heap, complexity is typically `O((V + E) log V)`.

#### Deep dive

Negative edges break Dijkstra's assumptions because a "finalized" shortest path could later become cheaper.

#### Production angle

Weighted shortest-path thinking appears in routing, cost-based selection and dependency planning, though backend interviews rarely require full implementation.

#### Traps / caveats

- Not valid with negative weights.
- Priority queue may contain stale entries.
- Define whether you need one target or all distances.

#### Optional Anki

Q: Main Dijkstra requirement?
A: Non-negative edge weights.

</details>
