# 15.06. Linked lists, LRU and pointer manipulation

---

<a id="alg-list-001"></a>

<details>
<summary><strong>ALG-LIST-001. What linked-list patterns are worth recognizing for Java backend interviews?</strong></summary>

#### Short answer

Know the common patterns, but do not over-prioritize linked lists for backend interviews.

#### Interview answer

The useful linked-list patterns are reversing a list, detecting cycles, finding a middle node, using dummy nodes and combining a list with a map for LRU-style caches. These tasks test pointer manipulation and invariants.

For senior Java backend interviews, linked lists are less central than collections, concurrency, databases and system design, but they still appear in coding screens.

#### Deep dive

In ordinary Java backend code, `LinkedList` is rarely the best collection. The interview data structure is often a custom node type, not `java.util.LinkedList`.

#### Production angle

The most practical linked-list idea is recency ordering in cache implementations.

#### Traps / caveats

- Do not claim `LinkedList` is generally faster than `ArrayList`.
- Watch null checks.
- Keep pointer updates small and deliberate.

#### Optional Anki

Q: Most practical linked-list interview pattern for backend work?
A: LRU cache with map plus doubly linked list.

</details>

<a id="alg-list-002"></a>

<details>
<summary><strong>🧠 ALG-LIST-002. How do you reverse a singly linked list?</strong></summary>

#### Short answer

Iterate through the list and reverse each `next` pointer while tracking previous, current and next nodes.

#### Interview answer

Use three references: `prev`, `cur` and `next`. For each node, save `cur.next` into `next`, set `cur.next = prev`, then move `prev = cur` and `cur = next`. When `cur` becomes null, `prev` is the new head.

This is `O(n)` time and `O(1)` extra space.

#### Deep dive

The recursive version is elegant but can overflow the stack on long lists.

#### Production angle

This is mostly a coding-screen exercise. The value is showing careful reference updates without losing the rest of the list.

#### Traps / caveats

- Save `next` before overwriting `cur.next`.
- Return the new head.
- Handle empty and one-node lists.

#### Optional Anki

Q: Three references for reversing a list?
A: `prev`, `cur`, `next`.

</details>

<a id="alg-list-003"></a>

<details>
<summary><strong>ALG-LIST-003. How do you detect a cycle in a linked list?</strong></summary>

#### Short answer

Use fast and slow pointers; if they meet, there is a cycle.

#### Interview answer

Move `slow` one step at a time and `fast` two steps at a time. If the list has no cycle, `fast` reaches null. If there is a cycle, `fast` eventually catches `slow` inside the cycle.

This is `O(n)` time and `O(1)` space.

#### Deep dive

A `HashSet` of visited nodes is simpler but uses `O(n)` extra memory.

#### Production angle

Cycle detection is rare in normal backend code but useful for reasoning about object graphs, linked structures and infinite traversals.

#### Traps / caveats

- Check `fast` and `fast.next` before advancing.
- Compare node references, not node values.
- A cycle can be one node pointing to itself.

#### Optional Anki

Q: Cycle detection without extra memory?
A: Fast and slow pointers.

</details>

<a id="alg-list-004"></a>

<details>
<summary><strong>ALG-LIST-004. Why are dummy nodes useful in linked-list algorithms?</strong></summary>

#### Short answer

Dummy nodes simplify edge cases around the head of the list.

#### Interview answer

A dummy node is a temporary node placed before the real head. It lets the algorithm treat inserting, removing or merging at the head the same as other positions. At the end, return `dummy.next`.

This reduces special cases and makes pointer code easier to reason about.

#### Deep dive

Dummy nodes are common in merge-two-lists, remove-nth-node and partition-list tasks.

#### Production angle

The general lesson is useful beyond linked lists: add a small sentinel or boundary object when it removes fragile branching.

#### Traps / caveats

- Return `dummy.next`, not `dummy`.
- Do not expose the dummy node as data.
- Still handle null input.

#### Optional Anki

Q: What problem does a dummy node solve?
A: Special handling for head insert/remove cases.

</details>

<details>
<summary><strong>ALG-LIST-005. How would you implement an LRU cache in Java, and when is `LinkedHashMap` enough?</strong></summary>

#### Short answer

Use a hash map plus recency order; in Java, `LinkedHashMap` can implement simple LRU behavior.

#### Interview answer

An LRU cache needs `get` and `put` in `O(1)` and eviction of the least recently used entry. The classic custom design uses a `HashMap<K, Node>` and a doubly linked list ordered by recency. On access, move the node to the front; on overflow, remove the tail.

For simple single-JVM cases, `LinkedHashMap` with access order, created with the constructor flag `accessOrder = true`, and `removeEldestEntry` is often enough.

#### Deep dive

`LinkedHashMap` is not a full production cache: no TTL, metrics, size-by-weight, async refresh or built-in thread safety.

#### Production angle

In real services, prefer a mature cache like Caffeine unless the task is specifically to implement LRU.

#### Traps / caveats

- Define capacity zero behavior.
- Make thread-safety explicit.
- Evict on put after updating recency.

#### Optional Anki

Q: Classic LRU structures?
A: Hash map plus doubly linked list.

</details>
