# 15.03. Prefix sums, two pointers and sliding windows

---

<a id="alg-pat-001"></a>

<details>
<summary><strong>ALG-PAT-001. What is a prefix sum, and what problems does it simplify?</strong></summary>

#### Short answer

A prefix sum stores cumulative totals so range sums can be answered quickly.

#### Interview answer

For an array, `prefix[i]` usually stores the sum of elements before index `i` or up to index `i`. Then a range sum can be computed by subtracting two prefix values instead of scanning the range again.

This turns repeated range-sum queries from `O(n)` each into `O(1)` after `O(n)` preprocessing.

#### Deep dive

A common convention is `prefix[0] = 0` and `prefix[i + 1] = prefix[i] + nums[i]`. Then sum `[l, r]` is `prefix[r + 1] - prefix[l]`.

#### Production angle

The same idea appears in cumulative metrics, report windows and precomputed aggregates.

#### Traps / caveats

- Pick one inclusive/exclusive convention.
- Sums can overflow `int`.
- Updates are expensive unless using a different structure.

#### Optional Anki

Q: Why use `prefix[0] = 0`?
A: It makes ranges starting at index 0 easy.

</details>

<a id="alg-pat-002"></a>

<details>
<summary><strong>ALG-PAT-002. How can prefix sums and a hash map solve subarray-sum problems?</strong></summary>

#### Short answer

Track prefix sums seen so far; a target subarray exists when `currentSum - target` was seen earlier.

#### Interview answer

If the sum from start to current index is `current`, and an earlier prefix sum was `current - target`, then the elements between that earlier point and the current index sum to `target`. Store prefix sums in a map or set as you scan.

For counting subarrays, store counts of prefix sums, not just existence.

#### Deep dive

This works even with negative numbers, unlike many sliding-window sum solutions.

#### Production angle

The pattern is useful whenever repeated aggregate differences can answer interval questions.

#### Traps / caveats

- Initialize prefix sum `0`.
- Use counts when multiple starts are possible.
- Use `long` if sums may overflow.

#### Optional Anki

Q: Prefix-sum condition for target subarray?
A: Earlier prefix equals `currentSum - target`.

</details>

<a id="alg-pat-003"></a>

<details>
<summary><strong>ALG-PAT-003. What is the two-pointers technique?</strong></summary>

#### Short answer

Two pointers scan a structure from one or both ends while maintaining an invariant.

#### Interview answer

Two pointers are useful when each pointer can move monotonically and the algorithm avoids checking every pair. Examples include merging sorted lists, removing duplicates from sorted arrays, partitioning, and finding a pair in a sorted array.

The key is that moving a pointer must safely discard part of the search space.

#### Deep dive

Pointers can move from both ends toward the middle, or one pointer can lag behind another.

#### Production angle

Two-pointer style appears in merge operations, stream reconciliation and ordered event processing.

#### Traps / caveats

- It usually needs ordering or a monotonic condition.
- Pointer movement rules must avoid infinite loops.
- Be explicit about inclusive boundaries.

#### Optional Anki

Q: What makes two pointers efficient?
A: Each pointer moves monotonically, avoiding repeated scans.

</details>

<a id="alg-pat-004"></a>

<details>
<summary><strong>ALG-PAT-004. When does two pointers work on a sorted array?</strong></summary>

#### Short answer

It works when sorted order tells you which pointer movement can safely eliminate candidates.

#### Interview answer

For pair-sum in a sorted array, start left at the smallest and right at the largest. If the sum is too small, move left to increase it. If too large, move right to decrease it. Sorting gives a monotonic relationship between movement and sum.

Without that monotonic property, two pointers can miss answers.

#### Deep dive

This pattern also applies to removing duplicates and merging sorted arrays because relative ordering is meaningful.

#### Production angle

Sorted input can avoid memory-heavy maps, but sorting unsorted input may change order and costs `O(n log n)`.

#### Traps / caveats

- Sorting may lose original indexes.
- Duplicates need deliberate handling.
- Do not apply blindly to unsorted data.

#### Optional Anki

Q: Why can pair-sum use two pointers on sorted input?
A: Moving left increases sum; moving right decreases sum.

</details>

<a id="alg-pat-005"></a>

<details>
<summary><strong>ALG-PAT-005. What is the fast-and-slow pointers technique?</strong></summary>

#### Short answer

Fast-and-slow pointers move at different speeds to detect structure such as cycles or midpoints.

#### Interview answer

In linked lists, one pointer can move one step and another two steps. If there is a cycle, they eventually meet. If there is no cycle, the fast pointer reaches the end. The same idea finds the middle of a list when the fast pointer finishes.

#### Deep dive

This is also called Floyd's cycle detection for the cycle case.

#### Production angle

The direct production use is rare, but it tests whether a candidate can reason about references and loop invariants.

#### Traps / caveats

- Check `fast != null` and `fast.next != null`.
- Do not dereference before null checks.
- Define behavior for even-length lists.

#### Optional Anki

Q: What does fast-and-slow detect in a list?
A: Cycles or the midpoint.

</details>

<a id="alg-pat-006"></a>

<details>
<summary><strong>ALG-PAT-006. What is the sliding window technique?</strong></summary>

#### Short answer

A sliding window maintains a contiguous range while moving its boundaries through the input.

#### Interview answer

Sliding window is useful for subarray or substring problems where the answer is contiguous. Instead of recomputing every range, maintain current state as the right boundary expands and the left boundary shrinks.

Examples include maximum sum of size `k`, longest substring without duplicates, and minimum window with required characters.

#### Deep dive

The algorithm depends on an invariant: what property the current window satisfies or is trying to satisfy.

#### Production angle

Sliding-window thinking appears in rate limiters, circuit breakers, rolling metrics and streaming validation.

#### Traps / caveats

- Not all subarray problems fit sliding window.
- Negative numbers can break sum-based monotonicity.
- Update counts when both entering and leaving.

#### Optional Anki

Q: What kind of result does sliding window usually find?
A: A contiguous subarray or substring.

</details>

<a id="alg-pat-007"></a>

<details>
<summary><strong>ALG-PAT-007. What is the difference between fixed-size and variable-size sliding windows?</strong></summary>

#### Short answer

Fixed-size windows keep a constant length; variable-size windows grow and shrink based on a condition.

#### Interview answer

For a fixed-size problem like "maximum sum of `k` elements," add the new element and remove the element that leaves when size exceeds `k`. For a variable-size problem like "longest valid substring," expand right, then shrink left until the invariant is restored.

The variable case is usually harder because the shrink rule matters.

#### Deep dive

Fixed windows often maintain a sum or count. Variable windows often maintain frequency maps, distinct counts or constraint violations.

#### Production angle

Fixed and rolling windows matter in monitoring, throttling and alerting logic.

#### Traps / caveats

- Off-by-one errors are common.
- Shrinking too early can miss answers.
- Shrinking too late can keep invalid state.

#### Optional Anki

Q: Fixed window example?
A: Maximum sum of exactly `k` consecutive elements.

</details>

<a id="alg-pat-008"></a>

<details>
<summary><strong>ALG-PAT-008. How do you decide when to expand and shrink a sliding window?</strong></summary>

#### Short answer

Expand to include new candidates; shrink when the window violates or no longer needs extra elements.

#### Interview answer

I define the invariant first. For "longest substring without duplicates," expand right and shrink left while a duplicate exists. For "minimum window containing all required characters," expand until valid, then shrink while still valid to minimize length.

The update order should match whether the problem asks for longest, shortest or count.

#### Deep dive

The best moment to update the answer depends on the invariant: after restoring validity for longest, or during shrinking for minimum valid windows.

#### Production angle

This mirrors stateful stream processing: define the valid state and update it consistently as events enter or expire.

#### Traps / caveats

- Forgetting to decrement outgoing counts.
- Updating answer while state is invalid.
- Mixing inclusive and exclusive indices.

#### Optional Anki

Q: First step in a sliding-window problem?
A: Define the window invariant.

</details>

<a id="alg-pat-009"></a>

<details>
<summary><strong>🧠 ALG-PAT-009. What makes minimum-window-substring style problems harder than ordinary sliding windows?</strong></summary>

#### Short answer

They require tracking required frequencies and shrinking only while all requirements remain satisfied.

#### Interview answer

In minimum-window problems, the window is valid only when it contains all required characters with enough counts. I maintain a need map, a window map and a counter for how many requirements are satisfied. After expanding to validity, I shrink left to find the smallest valid window.

The difficulty is not the loop itself; it is correct state updates.

#### Deep dive

Track satisfied keys, not just total characters, when duplicate required characters exist.

#### Production angle

The pattern resembles matching constraints over streaming data: required fields, quotas or windowed event conditions.

#### Traps / caveats

- Duplicates in the target string matter.
- Shrinking can invalidate the window.
- Updating the best answer at the wrong time gives invalid results.

#### Optional Anki

Q: Why is minimum window harder?
A: Validity depends on required frequencies, not just set membership.

</details>
