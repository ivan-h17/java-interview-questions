# 15.02. Arrays, strings, hash tables and collection choice

---

<a id="alg-ds-001"></a>

<details>
<summary><strong>ALG-DS-001. When is an array or `ArrayList` a good data structure for a coding task?</strong></summary>

#### Short answer

Use arrays or `ArrayList` when ordered indexed access and compact sequential storage matter.

#### Interview answer

An array is good when size is fixed or primitive storage matters. `ArrayList` is good when I need a resizable ordered list with fast random access and cheap append. Both are natural for scanning, sorting, two pointers, prefix sums and dynamic programming tables.

They are not good when frequent insertion/removal in the middle, uniqueness or key lookup is the main operation.

#### Deep dive

`ArrayList.get(i)` is `O(1)`, appending is amortized `O(1)`, but removing from the front or middle shifts elements and is `O(n)`.

#### Production angle

For API responses, arrays/lists also express stable order. For huge inputs, avoid materializing everything when streaming or pagination would be safer.

#### Traps / caveats

- `ArrayList` is not synchronized.
- Removing while iterating can fail.
- `LinkedList` is rarely faster in ordinary Java code.

#### Optional Anki

Q: Main strength of `ArrayList`?
A: Fast indexed access and amortized fast append.

</details>

<a id="alg-ds-002"></a>

<details>
<summary><strong>ALG-DS-002. How do you solve common frequency-counting problems in Java?</strong></summary>

#### Short answer

Use a `HashMap` from value to count, or an array if the value range is small and known.

#### Interview answer

For arbitrary keys, I use `Map<T, Integer>` and update with `merge(key, 1, Integer::sum)` or `getOrDefault`. For characters or small integer ranges, an `int[]` can be simpler and faster.

The key is to define what counts as the same value: exact string, normalized string, lowercase character, ID, or composite key.

#### Deep dive

For Unicode strings, counting `char` may be wrong because a user-visible character can span multiple code units. Interview tasks usually simplify this, but production text does not.

#### Production angle

Frequency maps appear in rate limiting, aggregation, validation, duplicate detection and metrics-like calculations.

#### Traps / caveats

- `char` is not always a full character.
- Counts can overflow for very large streams.
- Normalization rules must match the domain.

#### Optional Anki

Q: Java one-liner style for incrementing a map count?
A: `map.merge(key, 1, Integer::sum)`.

</details>

<a id="alg-ds-003"></a>

<details>
<summary><strong>ALG-DS-003. How do hash tables help solve lookup, deduplication and grouping problems?</strong></summary>

#### Short answer

Hash tables turn repeated linear search into expected constant-time lookup by key.

#### Interview answer

If a brute-force solution repeatedly asks "have I seen this?", "where is the matching item?", or "which bucket does this belong to?", a hash table is often the right structure. `HashSet` handles membership and deduplication. `HashMap` handles lookup, counting, grouping and indexes by ID.

The trade-off is extra memory and reliance on correct equality and hashing.

#### Deep dive

Expected lookup is `O(1)`, but bad hash distribution, expensive keys or broken `equals()`/`hashCode()` can hurt correctness and performance.

#### Production angle

Backend code often builds in-memory indexes for batch processing, joins between API data and database data, and request validation.

#### Traps / caveats

- `HashMap` order is not a stable API contract.
- Mutable keys can make entries unreachable.
- Duplicate keys need an explicit merge policy.

#### Optional Anki

Q: When does a `HashSet` help?
A: Fast membership tests and deduplication.

</details>

<a id="alg-ds-004"></a>

<details>
<summary><strong>ALG-DS-004. How would you solve the Two Sum problem, and what trade-offs does it have?</strong></summary>

#### Short answer

Scan once and store previously seen numbers in a map from value to index.

#### Interview answer

For each number `x`, compute `target - x` and check whether that complement was seen before. If yes, return the two indexes. If not, store `x` with its index and continue. This is `O(n)` time and `O(n)` space.

The brute-force nested-loop version is `O(n^2)` time and `O(1)` extra space.

#### Deep dive

If the input is sorted and indexes in sorted order are enough, two pointers can solve it in `O(n)` time and `O(1)` space. But sorting an unsorted array changes indexes unless you keep original positions.

#### Production angle

The pattern is more important than the toy problem: replace repeated searches with a map.

#### Traps / caveats

- Handle duplicates correctly.
- Store after checking to avoid using the same element twice.
- Watch integer overflow in `target - x`.

#### Optional Anki

Q: Two Sum map stores what?
A: Previously seen value to index.

</details>

<a id="alg-ds-005"></a>

<details>
<summary><strong>ALG-DS-005. How would you group anagrams efficiently?</strong></summary>

#### Short answer

Use a canonical key for each word and group words by that key in a map.

#### Interview answer

For each string, compute a key that is identical for anagrams. Common options are sorted characters or a frequency signature. Then use `Map<Key, List<String>>` and append each word to its group.

Sorting each word is simple: `O(k log k)` per word. A frequency key can be `O(k)` for a limited alphabet.

#### Deep dive

The key must be unambiguous. For frequency arrays, include separators or use a proper key object to avoid collisions like counts `1,11` versus `11,1`.

#### Production angle

This is a grouping-by-derived-key pattern used in report generation, deduplication and matching rules.

#### Traps / caveats

- Define case sensitivity.
- Define Unicode and locale assumptions.
- Avoid ambiguous string-built keys.

#### Optional Anki

Q: Main idea for grouping anagrams?
A: Group by a canonical representation.

</details>

<a id="alg-ds-006"></a>

<details>
<summary><strong>ALG-DS-006. How do you find duplicates or missing numbers in an array?</strong></summary>

#### Short answer

Use a set, frequency structure, sorting, or range-specific arithmetic depending on constraints.

#### Interview answer

If values are arbitrary, a `HashSet` detects duplicates in `O(n)` time and `O(n)` space. Sorting can find duplicates with `O(n log n)` time and less extra memory if mutation is allowed. If numbers are from a known small range, an array or bit set can work. For special "1..n with one missing" tasks, sums or XOR may work, but constraints must be clear.

#### Deep dive

Frequency maps handle multiple duplicates and counts. In-place marking can be efficient but is more error-prone and mutates input.

#### Production angle

For persisted data, database unique constraints are the real protection. In-memory duplicate checks are not enough under concurrency.

#### Traps / caveats

- Sum formulas can overflow.
- Sorting changes order.
- A `Set` does not explain how many duplicates exist.

#### Optional Anki

Q: General-purpose duplicate detection structure?
A: `HashSet`.

</details>

<a id="alg-ds-007"></a>

<details>
<summary><strong>ALG-DS-007. How do you remove duplicates from an array or list while preserving useful order?</strong></summary>

#### Short answer

Use `LinkedHashSet` or a `LinkedHashMap` keyed by the deduplication key.

#### Interview answer

If equality of the whole element is correct, `new ArrayList<>(new LinkedHashSet<>(items))` removes duplicates and keeps first-seen order. If deduplication should use a business key, use a `LinkedHashMap<K, V>` and decide whether first or last value wins.

The important part is making the order and merge policy explicit.

#### Deep dive

For sorted arrays, duplicates can be removed in place with two pointers, but that only preserves sorted order and assumes mutation is allowed.

#### Production angle

Stable deduplication matters for API responses, pagination and repeatable batch outputs.

#### Traps / caveats

- `HashSet` does not preserve order.
- Entity `equals()` may be unsafe for business deduplication.
- Silent deduplication can hide data quality issues.

#### Optional Anki

Q: Ordered deduplication collection?
A: `LinkedHashSet` or `LinkedHashMap`.

</details>

<a id="alg-ds-008"></a>

<details>
<summary><strong>ALG-DS-008. What string pitfalls matter in Java coding tasks?</strong></summary>

#### Short answer

Important pitfalls include immutability, `equals()` versus `==`, Unicode, substring/index boundaries and repeated concatenation.

#### Interview answer

`String` is immutable, so repeated concatenation in loops can create unnecessary objects; use `StringBuilder`. Compare content with `equals()`, not `==`. Be careful with indexes because `substring`, `charAt` and loops can produce off-by-one errors. If the task involves real text, `char` and length may not match user-perceived characters.

#### Deep dive

Java `String.length()` returns UTF-16 code units. This matters for Unicode-heavy production code, although many interview tasks assume ASCII or lowercase English letters.

#### Production angle

String bugs appear in IDs, normalization, search, request validation, logging and security-sensitive comparison.

#### Traps / caveats

- `==` compares references.
- Locale-sensitive lowercasing can surprise.
- Regex can be expensive or wrong for simple parsing.

#### Optional Anki

Q: How do you compare Java string content?
A: Use `equals()` or `Objects.equals()`.

</details>

<a id="alg-ds-009"></a>

<details>
<summary><strong>ALG-DS-009. When should you use `StringBuilder` instead of repeated string concatenation?</strong></summary>

#### Short answer

Use `StringBuilder` when building a string incrementally in a loop or across many steps.

#### Interview answer

For a few literals or simple expressions, `+` is fine and often optimized. In a loop, repeated `result += part` can create many intermediate strings because `String` is immutable. `StringBuilder` keeps a mutable buffer and appends efficiently.

In interviews, using `StringBuilder` also communicates that I understand the allocation cost.

#### Deep dive

Consider pre-sizing the builder if the final size is predictable and large.

#### Production angle

This matters in serialization-like code, report generation, log construction and text processing. For structured formats, prefer proper libraries over manual string building.

#### Traps / caveats

- `StringBuilder` is not thread-safe.
- Do not build SQL by string concatenation with user input.
- Readability still matters for small strings.

#### Optional Anki

Q: Why avoid `s += x` in a large loop?
A: It can allocate many intermediate strings.

</details>

<details>
<summary><strong>ALG-DS-010. When is a custom key object useful in a hash-map based solution?</strong></summary>

#### Short answer

Use a custom key when lookup depends on multiple fields or normalized values.

#### Interview answer

If a map key is a combination such as `(userId, productId)`, `(x, y)` or normalized `(country, phone)`, a small immutable key object is clearer and safer than concatenating strings. In modern Java, a record works well because it gives value-based `equals()` and `hashCode()` automatically.

#### Deep dive

The key should be immutable and should contain exactly the fields that define equality for the problem.

#### Production angle

Custom keys prevent accidental collisions and unclear separators in batch jobs, caches and grouping logic.

#### Traps / caveats

- Mutable map keys break lookup.
- String concatenation keys can collide.
- Entity objects are often poor map keys.

#### Optional Anki

Q: Good Java construct for a simple composite map key?
A: An immutable record.

</details>

<a id="alg-ds-011"></a>

<details>
<summary><strong>ALG-DS-011. How do you choose between `ArrayList`, `HashSet`, `HashMap`, `TreeMap` and `PriorityQueue`?</strong></summary>

#### Short answer

Choose by the operation you need: indexed order, uniqueness, key lookup, sorted keys or priority removal.

#### Interview answer

Use `ArrayList` for ordered indexed data. Use `HashSet` for membership and uniqueness. Use `HashMap` for lookup or grouping by key. Use `TreeMap` when keys must stay sorted or range queries are needed. Use `PriorityQueue` when you repeatedly need the smallest or largest item by priority.

I choose the structure based on required operations, not habit.

#### Deep dive

`TreeMap` is `O(log n)` and comparator-driven. `PriorityQueue` is not a sorted list; only polling repeatedly gives sorted order.

#### Production angle

The wrong collection can create latency, unstable ordering, duplicate data or broken pagination.

#### Traps / caveats

- `HashMap` iteration order is not a contract.
- `PriorityQueue` iteration is not sorted.
- `TreeMap` comparator affects key uniqueness.

#### Optional Anki

Q: Which collection for repeated top item by priority?
A: `PriorityQueue`.

</details>
