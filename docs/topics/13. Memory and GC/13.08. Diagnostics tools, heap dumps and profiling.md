# 13.08. Diagnostics tools, heap dumps and profiling

---

<a id="mem-tools-001"></a>

<details>
<summary><strong>MEM-TOOLS-001. What tools help analyze Java memory usage?</strong></summary>

#### Short answer

Useful tools include GC logs, JVM metrics, `jcmd`, heap dumps, class histograms, JFR, MAT, NMT and allocation profilers.

#### Interview answer

Start with low-risk signals: metrics, logs and GC logs. Use `jcmd` for runtime information, class histograms, heap dumps and JFR control. Use Eclipse MAT or similar tools for heap dump analysis. Use Native Memory Tracking for native memory. Use allocation profiling when the issue is churn rather than retention.

The tool depends on the question you are answering.

#### Deep dive

Heap dumps answer "what is retained now"; allocation profilers answer "what is being allocated over time"; NMT answers "where native memory is going".

#### Production angle

Prefer the least disruptive tool that can confirm or reject your hypothesis.

#### Traps / caveats

- A heap dump is not always the right first tool.
- Some tools require attach permissions.
- Diagnostics can pause or slow the service.

#### Optional Anki

Q: What tool helps with native memory categories?
A: Native Memory Tracking.

</details>

<a id="mem-tools-002"></a>

<details>
<summary><strong>MEM-TOOLS-002. What is a heap dump, and when is it useful?</strong></summary>

#### Short answer

A heap dump is a snapshot of heap objects and references, useful for retained-memory analysis.

#### Interview answer

A heap dump captures objects currently in the Java heap, their classes, fields and reference graph. It is useful when you suspect a heap leak, unexpectedly large live set, unbounded cache or retained object graph.

Tools such as Eclipse MAT can compute dominators and paths to GC roots.

#### Deep dive

Heap dumps show retained memory at one moment. They do not directly show allocation rate, CPU overhead or native memory.

#### Production angle

Capture dumps carefully because they can pause the process, be huge and contain sensitive data.

#### Traps / caveats

- A heap dump is not a native memory dump.
- One dump may not prove growth.
- Dump analysis needs business context.

#### Optional Anki

Q: What question does a heap dump answer well?
A: Which heap objects are retained and why.

</details>

<a id="mem-tools-003"></a>

<details>
<summary><strong>MEM-TOOLS-003. How can you obtain a heap dump safely?</strong></summary>

#### Short answer

Use controlled tooling such as `jcmd GC.heap_dump`, preconfigured OOME dumps or platform diagnostics, with attention to pause, disk and data sensitivity.

#### Interview answer

Common options are `jcmd <pid> GC.heap_dump <file>`, `jmap -dump`, JVM flags like `HeapDumpOnOutOfMemoryError`, or platform-specific mechanisms. In production, first check disk space, expected dump size, service criticality and whether the dump contains sensitive data.

If the service is too critical, consider taking one replica out of rotation first.

#### Deep dive

Heap dump capture can be stop-the-world and may take significant time for large heaps.

#### Production angle

Have a runbook: target directory, retention policy, encryption, access control and upload path.

#### Traps / caveats

- Capturing a dump can worsen an incident.
- Dumping into a small container filesystem can fail.
- The dump may expose secrets and customer data.

#### Optional Anki

Q: What should you check before taking a production heap dump?
A: Impact, disk space, dump size and data sensitivity.

</details>

<a id="mem-tools-004"></a>

<details>
<summary><strong>MEM-TOOLS-004. What is `jcmd`, and why is it useful?</strong></summary>

#### Short answer

`jcmd` is a JDK diagnostic command that can ask a running JVM for diagnostic data.

#### Interview answer

`jcmd` can list Java processes and run diagnostic commands such as printing JVM flags, command line, class histograms, heap information, thread dumps, JFR commands and native memory summaries.

It is often preferred over older tools because it centralizes many diagnostics.

#### Deep dive

The running JVM must allow attach, and permissions/container namespaces can prevent it.

#### Production angle

Useful commands include `VM.command_line`, `VM.flags`, `GC.class_histogram`, `GC.heap_dump`, `Thread.print`, `JFR.*` and `VM.native_memory`.

#### Traps / caveats

- Some commands are disruptive.
- Attach may be disabled or blocked.
- You must run it against the correct process/PID namespace.

#### Optional Anki

Q: What is `jcmd` used for?
A: Running diagnostic commands against a live JVM.

</details>

<a id="mem-tools-005"></a>

<details>
<summary><strong>MEM-TOOLS-005. What is Java Flight Recorder?</strong></summary>

#### Short answer

Java Flight Recorder is a low-overhead JVM event recording system for production diagnostics.

#### Interview answer

JFR records structured events from the JVM and application: allocation, GC, thread activity, locks, exceptions, I/O, method profiling and more. It is designed to be low overhead and suitable for production when configured carefully.

Java Mission Control or the `jfr` tool can analyze recordings.

#### Deep dive

JFR is timeline-based, so it helps correlate symptoms across CPU, GC, allocation and blocking events.

#### Production angle

JFR is often safer than immediately taking a heap dump when investigating latency, allocation rate or blocking.

#### Traps / caveats

- JFR files can still contain sensitive data.
- Recording settings affect overhead and detail.
- Very short recordings may miss intermittent issues.

#### Optional Anki

Q: What kind of diagnostic data does JFR record?
A: Structured JVM and application runtime events over time.

</details>

---

<a id="mem-tools-006"></a>

<details>
<summary><strong>MEM-TOOLS-006. When is JFR better than a heap dump?</strong></summary>

#### Short answer

JFR is better when you need timeline behavior: allocation rate, latency, blocking, GC correlation or CPU activity.

#### Interview answer

A heap dump shows what is retained at one instant. JFR shows what happened over time. If the problem is high allocation churn, p99 spikes, lock contention, slow I/O or GC correlation, JFR is usually more informative and less disruptive.

For retained-memory leaks, heap dumps are often better.

#### Deep dive

JFR can show allocation hotspots even when objects die quickly and never dominate a heap dump.

#### Production angle

Use JFR first for unclear production performance issues, then take a heap dump if retention becomes the main hypothesis.

#### Traps / caveats

- JFR does not replace heap dump dominator analysis.
- JFR settings must include the events you need.
- Long recordings need storage and privacy controls.

#### Optional Anki

Q: What is JFR better at than a heap dump?
A: Showing runtime events over time, such as allocation and latency.

</details>

<a id="mem-tools-007"></a>

<details>
<summary><strong>MEM-TOOLS-007. What is Eclipse MAT, and how does it help with memory leaks?</strong></summary>

#### Short answer

Eclipse MAT is a heap dump analyzer that helps find retained object graphs and leak suspects.

#### Interview answer

MAT loads heap dumps and computes object counts, shallow size, retained size, dominator tree and paths to GC roots. It helps identify which object or collection retains most memory and why it is still reachable.

It is useful for heap leaks and oversized live sets.

#### Deep dive

MAT's leak suspect report is a starting point, not proof. You still need to understand application ownership and expected caches.

#### Production angle

Use MAT to inspect retained caches, static maps, thread locals, request graphs, classloaders and large arrays.

#### Traps / caveats

- MAT needs enough local memory to open large dumps.
- Leak suspects can be false positives.
- Sensitive dumps must be handled securely.

#### Optional Anki

Q: What MAT view is commonly useful for leak analysis?
A: Dominator tree and paths to GC roots.

</details>

<a id="mem-tools-008"></a>

<details>
<summary><strong>MEM-TOOLS-008. How do you analyze a heap dump for a memory leak?</strong></summary>

#### Short answer

Find the largest retained graphs, inspect dominators and trace paths to GC roots.

#### Interview answer

I start with dominator tree and retained size, not just object count. Then I inspect suspicious owners: caches, static fields, thread locals, queues, classloaders and large arrays. Paths to GC roots show why the objects cannot be collected.

If possible, compare dumps over time to identify growth.

#### Deep dive

Business context matters. A large cache may be expected; an unbounded cache or unexpected key cardinality is the problem.

#### Production angle

Tie dump evidence to metrics: cache size, queue length, tenant traffic, deployment time and endpoint behavior.

#### Traps / caveats

- Biggest class by count may not retain the most memory.
- One dump can confuse peak load with a leak.
- Native memory is not explained by heap dump alone.

#### Optional Anki

Q: What is more useful than object count in leak analysis?
A: Retained size and path to GC roots.

</details>

<a id="mem-tools-009"></a>

<details>
<summary><strong>MEM-TOOLS-009. Why can heap dump capture be dangerous in production?</strong></summary>

#### Short answer

It can pause the JVM, consume CPU/I/O, fill disk and expose sensitive data.

#### Interview answer

Heap dump capture may require a stop-the-world pause and writes a large file. For a large heap, this can take significant time and stress the node or container storage. The dump contains object contents, including secrets, tokens and customer data.

It is powerful but operationally risky.

#### Deep dive

In a replicated service, it is safer to remove one instance from load balancing before capture if possible.

#### Production angle

Plan dump location, storage quota, encryption, access policy and retention before incidents.

#### Traps / caveats

- Dump size can approach or exceed heap size.
- Dump capture can trigger more failures.
- Heap dumps are not safe to share casually.

#### Optional Anki

Q: Name one operational and one security risk of heap dumps.
A: They can pause/fill storage and expose sensitive data.

</details>

<a id="mem-tools-010"></a>

<details>
<summary><strong>MEM-TOOLS-010. What sensitive data can appear in a heap dump?</strong></summary>

#### Short answer

Heap dumps can contain anything in memory: passwords, tokens, PII, request bodies, headers, keys and business data.

#### Interview answer

A heap dump is a memory snapshot of Java objects. It may include authentication tokens, database credentials, encryption keys, cookies, user data, payment data, payloads, logs, cached responses and internal configuration.

Treat it as sensitive production data.

#### Deep dive

Even if application logs redact secrets, heap objects may contain original unredacted strings or byte arrays.

#### Production angle

Restrict access, encrypt at rest, store in approved locations, set retention and avoid sending dumps through unapproved channels.

#### Traps / caveats

- Sanitizing dumps is difficult.
- Developers may not realize cache/request data is included.
- Dump analysis vendors/tools need security review.

#### Optional Anki

Q: Why should heap dumps be access-controlled?
A: They may contain secrets and customer data.

</details>

<a id="mem-tools-011"></a>

<details>
<summary><strong>MEM-TOOLS-011. How can you capture memory diagnostics in Kubernetes?</strong></summary>

#### Short answer

Use logs, metrics, `kubectl` evidence, exec/debug access, JVM tools in the image or sidecar/debug containers.

#### Interview answer

First collect Kubernetes events, pod status, restart reason, memory limits and container RSS. For JVM evidence, use exposed metrics, GC logs, JFR, heap dumps or `jcmd` if the tools and permissions are available.

You may need an image with JDK tools or an ephemeral debug container with the right namespace access.

#### Deep dive

Attach tools can fail because of PID namespaces, different users, missing JDK tools or disabled attach mechanisms.

#### Production angle

Prepare diagnostic capabilities before incidents: JVM flags, dump paths, persistent storage, runbooks and RBAC.

#### Traps / caveats

- Minimal JRE images may not include `jcmd`.
- OOMKilled can remove evidence before you exec in.
- Heap dumps in ephemeral storage can disappear or fill the node.

#### Optional Anki

Q: Why can `jcmd` fail in Kubernetes?
A: Missing tools, permissions, users or PID namespace issues.

</details>

<a id="mem-tools-012"></a>

<details>
<summary><strong>🧠 MEM-TOOLS-012. What is Native Memory Tracking?</strong></summary>

#### Short answer

Native Memory Tracking is a HotSpot feature that categorizes JVM native memory usage.

#### Interview answer

NMT can show native memory categories such as Java heap reservation, Class/Metaspace, Thread, Code, GC, Compiler, Internal and others. It helps explain why process memory is larger than heap usage.

It usually must be enabled at JVM startup with `-XX:NativeMemoryTracking=summary` or `-XX:NativeMemoryTracking=detail`.

#### Deep dive

NMT has summary and detail modes. Detail mode has more overhead. Output distinguishes reserved and committed memory.

#### Production angle

Use NMT when RSS grows but heap is stable, or when investigating Metaspace, thread stacks, Code Cache or JVM-native memory.

#### Traps / caveats

- NMT does not show every third-party native allocation perfectly.
- It may not be enabled after the fact; plan startup flags before incidents.
- Reserved memory is not the same as resident memory.

#### Optional Anki

Q: What problem does NMT help diagnose?
A: Native memory usage outside Java heap.

</details>

<a id="mem-tools-013"></a>

<details>
<summary><strong>🧠 MEM-TOOLS-013. How do you use `jcmd VM.native_memory`?</strong></summary>

#### Short answer

Use it to print native memory summaries or compare changes after taking a baseline.

#### Interview answer

If NMT is enabled with `-XX:NativeMemoryTracking=summary` or `detail`, `jcmd <pid> VM.native_memory summary` shows native memory categories. `baseline` records a point in time, and `summary.diff` shows changes since the baseline.

This is useful for native memory growth investigations.

#### Deep dive

Use `scale=MB` or similar options for readability. Detail mode can provide call-site detail but costs more overhead.

#### Production angle

Capture NMT alongside RSS, heap metrics, thread count and direct memory metrics to avoid misdiagnosing native growth as a heap leak.

#### Traps / caveats

- NMT must generally be enabled at startup.
- It adds overhead, especially in detail mode.
- NMT categories require interpretation.

#### Optional Anki

Q: What does `summary.diff` show?
A: Native memory changes since the NMT baseline.

</details>

<a id="mem-tools-014"></a>

<details>
<summary><strong>🧠 MEM-TOOLS-014. What is async-profiler allocation profiling?</strong></summary>

#### Short answer

It samples allocation events to show where objects are being allocated.

#### Interview answer

Async-profiler can profile allocation pressure and produce flame graphs showing allocation hotspots. This is useful when heap is not leaking but GC CPU is high because the service creates too many temporary objects.

It answers "where allocations come from" rather than "what is retained now".

#### Deep dive

Allocation profiling complements heap dumps. Heap dumps can miss short-lived objects because they are already dead by the time the dump is taken.

#### Production angle

Use allocation profiling to optimize hot request paths, serialization, mapping, collections or logging that create excessive garbage.

#### Traps / caveats

- Sampling may miss small or rare allocations.
- Profiling adds overhead.
- Optimize only hotspots that matter under realistic load.

#### Optional Anki

Q: When is allocation profiling better than a heap dump?
A: When objects die quickly but allocation rate is high.

</details>
