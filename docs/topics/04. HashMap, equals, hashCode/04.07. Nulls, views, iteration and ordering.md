# 04.07. Nulls, views, iteration and ordering

---

<a id="hm-null-001"></a>

<details>
<summary><strong>HM-NULL-001. Can `HashMap` store null keys and null values?</strong></summary>

#### Short answer

Yes. `HashMap` allows one null key and multiple null values.

#### Interview answer

`HashMap` permits a null key because keys are unique, so there can be at most one null key. It also permits any number of null values because different keys can map to null.

This differs from `ConcurrentHashMap`, which does not allow null keys or null values.

#### Deep dive

The null key is handled as a special key with hash `0`. Null values are ordinary stored values, but they make `get()` ambiguous because null can mean absent or present with a null value.

#### Production angle

Null values often make cache and configuration code harder to reason about. Consider using absence, `Optional` at API boundaries, or a sentinel value when the distinction matters.

#### Traps / caveats

- Only one null key is possible.
- Many null values are possible.
- Null values make `containsKey()` important.

#### Optional Anki

Q: How many null keys can a `HashMap` contain?
A: At most one.

</details>

<a id="hm-null-002"></a>

<details>
<summary><strong>HM-NULL-002. How does `get()` behave when a key is absent versus mapped to null?</strong></summary>

#### Short answer

`get()` returns null in both cases, so it cannot distinguish absent from present-with-null.

#### Interview answer

If a key is absent, `map.get(key)` returns null. If the key exists and its value is null, `map.get(key)` also returns null. Use `containsKey()` when you need to know whether the mapping exists.

#### Deep dive

This ambiguity is one reason `ConcurrentHashMap` forbids null values. In concurrent code, a null return can cleanly mean "no mapping" without needing a separate check that may race.

#### Production angle

This matters in caches. A null can mean "not cached" or "cached negative result." Mixing those meanings causes repeated database calls or incorrect behavior.

#### Traps / caveats

- `get()` alone is not enough when null values are allowed.
- `containsValue(null)` is not a substitute for `containsKey(key)`.
- Null-caching should be explicit.

#### Optional Anki

Q: How do you distinguish absent key from null value?
A: Use `containsKey()`.

</details>

<a id="hm-null-003"></a>

<details>
<summary><strong>HM-NULL-003. Why can null values make `containsKey()` necessary?</strong></summary>

#### Short answer

Because `get()` returns null for both missing keys and keys mapped to null.

#### Interview answer

If null values are allowed, `containsKey()` is the operation that tells whether a mapping exists. `get()` tells the value, but null is ambiguous. For example, `map.containsKey(id)` can be true while `map.get(id)` is null.

#### Deep dive

The common pattern is:

```java
if (map.containsKey(key)) {
    value = map.get(key);
}
```

In concurrent maps, this check-then-act pattern can be unsafe if the map can change between calls. For `HashMap` in single-threaded use, it is fine.

#### Production angle

Null ambiguity can create subtle bugs in negative caching and configuration resolution. Explicitly model absent, null and computed-empty cases.

#### Traps / caveats

- `containsKey()` checks key presence, not value non-nullness.
- `containsValue()` is usually linear time.
- For concurrent code, prefer atomic map methods where possible.

#### Optional Anki

Q: What does `containsKey()` answer?
A: Whether a key has a mapping, even if the value is null.

</details>

<a id="hm-null-004"></a>

<details>
<summary><strong>HM-NULL-004. What is the difference between `get()` and `getOrDefault()`?</strong></summary>

#### Short answer

`get()` returns the mapped value or null. `getOrDefault()` returns the mapped value if present, otherwise the supplied default.

#### Interview answer

`getOrDefault(key, defaultValue)` is useful when absence should produce a fallback. But if a key is present and mapped to null, `getOrDefault()` returns null, not the default, in `HashMap`.

So `getOrDefault()` handles absence, not "null value replacement."

#### Deep dive

If you want to treat null values as missing, you need explicit logic or avoid storing nulls. `Map` default methods such as `computeIfAbsent()` also have special behavior around nulls that should be understood before using them.

#### Production angle

This matters for default configuration and metrics counters. A present null can bypass a default unexpectedly.

#### Traps / caveats

- `getOrDefault()` does not replace present null values with the default.
- The default argument is evaluated before the method call.
- Use `computeIfAbsent()` carefully if null-producing mapping functions are possible.

#### Optional Anki

Q: What does `getOrDefault()` return for a present key mapped to null?
A: Null.

</details>

<a id="hm-null-005"></a>

<details>
<summary><strong>HM-NULL-005. What is the difference between `containsKey()` and `containsValue()`?</strong></summary>

#### Short answer

`containsKey()` checks for a key using hashing. `containsValue()` scans values and is usually linear time.

#### Interview answer

`containsKey(key)` follows the normal hash lookup path and is expected constant time with good keys. `containsValue(value)` has no hash index by value, so `HashMap` must scan entries until it finds a matching value.

Use `containsKey()` for lookup by key. Avoid frequent `containsValue()` on large maps.

#### Deep dive

Values are not unique and are not indexed by `HashMap`. Multiple keys can map to the same value. If you need efficient reverse lookup, maintain another map or use a bidirectional map abstraction with clear consistency rules.

#### Production angle

Repeated `containsValue()` inside loops can accidentally create quadratic behavior. This appears in validation, deduplication and mapping code.

#### Traps / caveats

- `containsValue()` uses value equality, not key equality.
- Null values are allowed in `HashMap`.
- Reverse lookup needs a different data model.

#### Optional Anki

Q: Which is usually faster in `HashMap`, `containsKey()` or `containsValue()`?
A: `containsKey()`.

</details>

<a id="hm-null-006"></a>

<details>
<summary><strong>HM-NULL-006. Can `ConcurrentHashMap` store null keys or null values, and why?</strong></summary>

#### Short answer

No. `ConcurrentHashMap` forbids null keys and null values to avoid ambiguity in concurrent operations.

#### Interview answer

In `ConcurrentHashMap`, a null return from `get()` means no mapping. If null values were allowed, a caller could not distinguish "missing" from "mapped to null" without a separate `containsKey()` check, and that check could race with concurrent updates.

Forbidding nulls makes concurrent semantics clearer and supports atomic operations.

#### Deep dive

This design also applies to many concurrent map methods where null has special meaning, such as mapping functions returning null to indicate no mapping should be recorded.

#### Production angle

When migrating from `HashMap` to `ConcurrentHashMap`, null keys or values may cause `NullPointerException`. Model absence explicitly.

#### Traps / caveats

- `Collections.synchronizedMap(new HashMap<>())` can still allow nulls.
- `ConcurrentHashMap.get()` returning null means absent.
- Mapping functions should not return null unless removal/no-mapping semantics are intended.

#### Optional Anki

Q: Why does `ConcurrentHashMap` forbid null values?
A: To make null return unambiguously mean absent under concurrency.

</details>

<a id="hm-iter-001"></a>

<details>
<summary><strong>HM-ITER-001. How does `HashMap` iteration work?</strong></summary>

#### Short answer

`HashMap` iteration walks the internal bucket table and returns keys, values or entries from the chosen view.

#### Interview answer

You can iterate through `keySet()`, `values()` or `entrySet()`. Internally, the iterator scans buckets and entries in bucket structures. The order is based on internal table layout and is not guaranteed.

If both key and value are needed, iterating `entrySet()` is usually best.

#### Deep dive

Iteration cost is related to capacity plus size because the iterator has to move across the table and entries. This is why a very sparse oversized map can be slower to iterate than expected.

#### Production angle

Do not expose API response order from a plain `HashMap`. Use `LinkedHashMap`, `TreeMap` or explicit sorting when order matters.

#### Traps / caveats

- Iteration order is unspecified.
- Iterators are fail-fast on structural modification.
- Large unused capacity can hurt iteration.

#### Optional Anki

Q: Which view is best when both key and value are needed?
A: `entrySet()`.

</details>

<a id="hm-iter-002"></a>

<details>
<summary><strong>HM-ITER-002. What is `ConcurrentModificationException` in `HashMap` iteration?</strong></summary>

#### Short answer

It is a fail-fast exception thrown when an iterator detects structural modification outside the iterator.

#### Interview answer

If you create an iterator over a `HashMap` and then add or remove mappings through the map directly, the iterator may throw `ConcurrentModificationException`. It is not limited to multi-threading; a single thread can trigger it by modifying the map during iteration.

#### Deep dive

The iterator compares an expected structural modification count with the map's current count. If they differ, it fails. This is best-effort bug detection, not a synchronization guarantee.

#### Production angle

This often happens in cleanup code that loops over entries and calls `map.remove(key)`. Use iterator removal or `entrySet().removeIf(...)`.

#### Traps / caveats

- The exception does not prove a data race.
- Fail-fast behavior is not guaranteed in all races.
- Value replacement is usually not structural modification.

#### Optional Anki

Q: Can one thread trigger `ConcurrentModificationException`?
A: Yes, by structurally modifying a map during iteration.

</details>

<a id="hm-iter-003"></a>

<details>
<summary><strong>HM-ITER-003. How do you remove entries while iterating over a `HashMap`?</strong></summary>

#### Short answer

Use the iterator's `remove()` method or a supported bulk operation such as `entrySet().removeIf(...)`.

#### Interview answer

Do not call `map.remove(key)` inside an enhanced `for` loop over the same map. Instead, use an explicit iterator:

```java
Iterator<Map.Entry<K, V>> it = map.entrySet().iterator();
while (it.hasNext()) {
    if (shouldRemove(it.next())) {
        it.remove();
    }
}
```

For simple predicates, `map.entrySet().removeIf(predicate)` is often clearer.

#### Deep dive

The iterator updates its expected modification count when its own `remove()` is used. Direct map removal changes the map behind the iterator and can trigger fail-fast behavior.

#### Production angle

Safe removal patterns prevent intermittent cleanup failures in caches, batch jobs and request aggregation maps.

#### Traps / caveats

- Do not remove twice for the same iterator position.
- `removeIf` still mutates the underlying map.
- For concurrent maps, iteration semantics are different.

#### Optional Anki

Q: What removal method is safe during `HashMap` iterator traversal?
A: `Iterator.remove()`.

</details>

<a id="hm-iter-004"></a>

<details>
<summary><strong>HM-ITER-004. What is the difference between iterating over `keySet()` and `entrySet()`?</strong></summary>

#### Short answer

`keySet()` gives keys only; `entrySet()` gives key-value pairs and avoids extra lookups when values are needed.

#### Interview answer

If you only need keys, `keySet()` is fine. If you need both key and value, use `entrySet()` because each entry already contains both. Iterating keys and calling `map.get(key)` adds an extra lookup for every entry.

#### Deep dive

The extra lookup may not matter for small maps, but it is unnecessary and can hurt large or collision-heavy maps. `values()` is best when keys are irrelevant.

#### Production angle

Prefer `entrySet()` in review when code loops over keys only to fetch values. It is clearer and usually cheaper.

#### Traps / caveats

- `entrySet()` entries are backed by the map.
- Changing values through entries may affect the map.
- `keySet()` removal removes mappings.

#### Optional Anki

Q: Why prefer `entrySet()` when values are needed?
A: It avoids an extra `get()` lookup per key.

</details>

<a id="hm-iter-005"></a>

<details>
<summary><strong>HM-ITER-005. How can you preserve insertion order in a map?</strong></summary>

#### Short answer

Use `LinkedHashMap`.

#### Interview answer

`LinkedHashMap` maintains a linked list of entries in insertion order by default. It has `HashMap`-like lookup characteristics plus extra links for predictable iteration order.

It can also be configured for access order, which is useful for simple LRU-style behavior.

#### Deep dive

Insertion order means updating an existing key does not normally move it. Access order means reads and writes can move entries to the end. For serious caching, use a cache library rather than hand-rolled `LinkedHashMap` unless requirements are simple.

#### Production angle

Use `LinkedHashMap` for stable JSON output, predictable tests, ordered processing or preserving database/result order after indexing.

#### Traps / caveats

- `HashMap` order is not insertion order.
- `LinkedHashMap` uses more memory than `HashMap`.
- Access-order maps mutate order on reads.

#### Optional Anki

Q: Which standard map preserves insertion order?
A: `LinkedHashMap`.

</details>

<a id="hm-iter-006"></a>

<details>
<summary><strong>HM-ITER-006. How can you preserve sorted order in a map?</strong></summary>

#### Short answer

Use `TreeMap` or another `SortedMap`/`NavigableMap` implementation.

#### Interview answer

`TreeMap` keeps keys sorted by natural ordering or by a supplied `Comparator`. It supports ordered operations such as first key, last key, ranges, floor and ceiling lookups.

This is different from `HashMap`, which has no sorted iteration guarantee.

#### Deep dive

`TreeMap` operations are typically `O(log n)`, while `HashMap` expected lookup is `O(1)`. Sorted order costs more per operation but provides range-query behavior that hashing cannot.

#### Production angle

Use `TreeMap` for in-memory range lookups, sorted output or nearest-key queries. For large persistent data, use database indexes instead.

#### Traps / caveats

- Comparator consistency with `equals()` matters.
- `TreeMap` does not allow non-comparable keys without a comparator.
- Sorted order is not insertion order.

#### Optional Anki

Q: Which map gives sorted key order?
A: `TreeMap`.

</details>
