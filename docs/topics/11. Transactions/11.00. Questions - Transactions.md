# Transactions — Senior Question List

Target level: **Senior Java Backend Developer**

This is an English-first root question file for the `java-interview-questions` repository.

## Legend

- 🔥 **Bold questions** = Priority 1 / must know for the first pass.
- Regular questions = Priority 2 / recommended for deeper preparation.
- The list intentionally keeps both levels:
  - definition questions: “What is it?”
  - deep-dive questions: “How does it work under the hood?”
  - production questions: “What can go wrong and how would you debug it?”

## Source scope

This topic starts from the original PDF questions **240–261** and expands them into a senior-level transaction checklist.

Original PDF coverage:

- ACID
- transaction isolation levels
- Read Uncommitted, Read Committed, Repeatable Read, Serializable
- Dirty Read, Non-Repeatable Read, Phantom Read, Lost Update
- default isolation level in PostgreSQL
- default isolation level in MySQL
- Spring transaction propagation
- `Propagation.NESTED`
- `REQUIRED` vs `REQUIRES_NEW`
- `@Transactional`
- where `@Transactional` can be used
- rollback behavior
- rollback for runtime vs checked exceptions
- `readOnly` transactions
- `@Transactional` self-invocation

Senior-level expansion adds:

- transaction boundaries and service-layer design
- database-specific isolation behavior in PostgreSQL and MySQL/InnoDB
- MVCC, locks, deadlocks, serialization failures and retry logic
- Spring transaction manager internals
- proxy mechanics and self-invocation traps
- propagation modes and savepoints
- rollback rules and exception translation
- JPA/Hibernate persistence context and flush behavior
- optimistic/pessimistic locking
- distributed transactions, Saga and compensation
- Transactional Outbox, Inbox and idempotency
- connection pool impact and transaction performance
- testing transaction behavior with real databases
- production troubleshooting scenarios
