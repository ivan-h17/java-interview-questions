# 05.04. String construction and conversion

---

<a id="str-create-001"></a>

<details>
<summary><strong>STR-CREATE-001. What happens when a `String` is created from a `char[]`, and why does copying matter?</strong></summary>

#### Short answer

The constructor creates a string from the characters and copies the input so later array changes do not mutate the string.

#### Interview answer

When you create a `String` from a `char[]`, Java reads the characters and creates an immutable string value. It must not keep a mutable reference that lets external code change string contents through the original array.

Copying preserves the immutability contract.

#### Deep dive

Older and newer JDK internals differ, especially because modern strings may use compact byte storage internally. But the public contract is what matters: changing the original `char[]` after construction does not change the `String`.

#### Production angle

This matters when handling buffers, parsers and secrets. A `String` made from a password array cannot be cleared by clearing the original array; the string has its own managed storage.

#### Traps / caveats

- Do not rely on internal storage type.
- `toCharArray()` also returns a copy.
- Creating a string from a secret array may leave an extra secret copy in memory.

#### Optional Anki

Q: Does changing the original `char[]` change a `String` built from it?
A: No. The string value remains unchanged.

</details>

<a id="str-create-002"></a>

<details>
<summary><strong>STR-CREATE-002. What happens when a `String` is created from a `byte[]`, and why should you specify a `Charset`?</strong></summary>

#### Short answer

Bytes are decoded into text using a charset. Specify the charset so decoding is deterministic and protocol-correct.

#### Interview answer

A `byte[]` is binary data. To create a `String`, Java must decode those bytes using a character encoding such as UTF-8. If you use a constructor without a charset, Java uses the JVM default charset. In Java 17 and earlier that default was environment-dependent; in Java 18+ it is specified as UTF-8 unless configured otherwise.

Use `new String(bytes, StandardCharsets.UTF_8)` or the charset required by the protocol.

#### Deep dive

Wrong decoding can corrupt text or replace invalid sequences. The reverse operation also needs an explicit charset: `s.getBytes(StandardCharsets.UTF_8)`.

#### Production angle

Encoding bugs often appear only with non-English text, Java version changes, file imports or integrations with legacy systems. Explicit charsets make the protocol or file contract visible instead of relying on runtime defaults.

#### Traps / caveats

- Not all bytes are valid UTF-8.
- The database, HTTP header, file format and application must agree on encoding.
- Do not use strings to hold arbitrary binary data.

#### Optional Anki

Q: Why avoid `new String(bytes)`?
A: It uses the JVM default charset instead of the charset required by the data format.

</details>

<details>
<summary><strong>STR-CREATE-003. What is the difference between `String.valueOf(obj)`, `obj.toString()` and `Objects.toString(obj)`?</strong></summary>

#### Short answer

`obj.toString()` throws on null. `String.valueOf(obj)` returns `"null"` for null. `Objects.toString(obj)` also handles null and can take a default.

#### Interview answer

If `obj` is non-null, all three generally use `obj.toString()`. If `obj` is null, `obj.toString()` throws `NullPointerException`, while `String.valueOf(obj)` returns the literal string `"null"`. `Objects.toString(obj)` also returns `"null"` by default, and `Objects.toString(obj, defaultValue)` lets you choose another fallback.

#### Deep dive

`String.valueOf()` is used heavily by concatenation and builders. That is why `"value=" + null` produces `"value=null"` rather than throwing.

#### Production angle

The literal `"null"` can accidentally leak into logs, files, API responses or database fields. That may be acceptable for diagnostics but bad for domain data.

#### Traps / caveats

- `"null"` is a real string, not null.
- Null-safe conversion is not validation.
- Use explicit handling when null has business meaning.

#### Optional Anki

Q: What does `String.valueOf((Object) null)` return?
A: The string `"null"`.

</details>

<a id="str-create-004"></a>

<details>
<summary><strong>STR-CREATE-004. What are `String.join()` and `StringJoiner` used for?</strong></summary>

#### Short answer

They build delimiter-separated strings without manual delimiter bookkeeping.

#### Interview answer

`String.join()` is convenient for joining known strings with a delimiter, such as `String.join(",", values)`. `StringJoiner` gives more control, including prefix and suffix, and is used internally by some collectors.

They avoid common bugs like adding an extra delimiter at the end.

#### Deep dive

`String.join()` expects character sequences and does not perform CSV, JSON or SQL escaping. It joins text; it does not make structured output safe.

#### Production angle

Use these APIs for simple display strings, logs or controlled delimiter-separated values. Use real libraries for CSV, JSON, XML and SQL because escaping rules matter.

#### Traps / caveats

- Joining does not escape delimiter characters inside values.
- Null handling may surprise depending on the overload and inputs.
- Do not build SQL `IN` clauses by blindly joining user values.

#### Optional Anki

Q: What problem does `String.join()` solve?
A: Building delimiter-separated text without manual delimiter handling.

</details>

<a id="str-create-005"></a>

<details>
<summary><strong>STR-CREATE-005. When should you use `String.format()` or `formatted()`?</strong></summary>

#### Short answer

Use them when format patterns, alignment, number formatting or readability matter more than raw speed.

#### Interview answer

`String.format()` creates a formatted string using format specifiers. `"Hello %s".formatted(name)` is the instance-method variant. They are useful for human-readable messages, diagnostics and formatting with width or precision.

For simple hot-path concatenation, they are often slower and heavier than `+` or `StringBuilder`.

#### Deep dive

Formatting can be locale-sensitive depending on the overload and conversions. It also parses the format pattern and allocates supporting objects, so it should not be used blindly in tight loops.

#### Production angle

For logs, prefer parameterized logging instead of eagerly building formatted strings. For user-visible localized text, use a localization/message framework rather than hardcoded format strings scattered through code.

#### Traps / caveats

- Format strings can throw runtime exceptions if arguments do not match.
- Formatting is not escaping.
- Do not use `String.format()` for SQL construction.

#### Optional Anki

Q: What is `formatted()`?
A: An instance method equivalent in spirit to formatting the string as a format pattern.

</details>

<a id="str-create-006"></a>

<details>
<summary><strong>STR-CREATE-006. When should you avoid creating many temporary strings?</strong></summary>

#### Short answer

Avoid it in hot loops, large parsing jobs, high-throughput request paths and memory-sensitive code.

#### Interview answer

Temporary strings are cheap individually but expensive at scale. Repeated concatenation, regex splitting, substring-heavy parsing, formatting and logging can create many short-lived objects. That increases allocation rate and GC pressure.

#### Deep dive

Modern JVMs optimize many cases, so manual optimization should be based on profiling. But in large imports, CSV parsing, JSON processing and request pipelines, string allocation can become a real bottleneck.

#### Production angle

Use streaming parsers, `StringBuilder` with reasonable capacity, precompiled patterns, parameterized logging and domain-specific libraries. Measure allocation rate, GC pauses and CPU before and after changes.

#### Traps / caveats

- Do not make simple code complex without evidence.
- Avoid manual JSON or CSV construction when libraries can stream safely.
- Caching strings can trade allocation problems for memory leaks.

#### Optional Anki

Q: What is the production symptom of too many temporary strings?
A: High allocation rate, GC pressure and sometimes higher latency.

</details>
