# Glossary RU / EN

## Core SQL And Relational Model

| RU | EN | Notes |
| --- | --- | --- |
| декларативный язык | declarative language | Describes the desired result, not step-by-step execution. |
| реляционная база данных | relational database | A database model based on tables, rows, columns, relations, and constraints. |
| СУБД | DBMS | Database Management System. |
| отсутствующее / неизвестное значение | NULL | SQL marker for absent, unknown, or not applicable value. |
| трехзначная логика | three-valued logic | SQL boolean logic with `TRUE`, `FALSE`, and `UNKNOWN`. |

## SQL Command Groups

| RU | EN | Notes |
| --- | --- | --- |
| определение данных / изменение структуры | DDL / Data Definition Language | SQL commands for schema objects: `CREATE`, `ALTER`, `DROP`. |
| манипуляция данными / работа со строками | DML / Data Manipulation Language | SQL commands for reading and modifying rows: `SELECT`, `INSERT`, `UPDATE`, `DELETE`. |
| управление доступом | DCL / Data Control Language | SQL commands for permissions: `GRANT`, `REVOKE`. |
| управление транзакциями | TCL / Transaction Control Language | SQL commands for transaction boundaries: `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`. |

## Constraints And Keys

| RU | EN | Notes |
| --- | --- | --- |
| ограничение | constraint | Database rule that protects data integrity. |
| первичный ключ | primary key | Main non-null unique identifier of a table row. |
| уникальное ограничение | unique constraint | Rule that prevents duplicate values according to DBMS null semantics. |
| внешний ключ | foreign key | Constraint that enforces referential integrity between tables. |
| суррогатный ключ | surrogate key | Artificial identifier without business meaning. |
| естественный ключ | natural key | Business-meaningful unique identifier. |
| составной ключ | composite key | Key made from multiple columns. |

## Querying And Execution

| RU | EN | Notes |
| --- | --- | --- |
| план выполнения запроса | query execution plan | Physical plan chosen by the database optimizer. |
| оптимизатор запросов | query optimizer | DBMS component that chooses how to execute a query. |
| агрегатная функция | aggregate function | Function that calculates one value from multiple rows. |
| операция над множествами | set operation | SQL operations such as `UNION`, `INTERSECT`, and `EXCEPT`. |
| общее табличное выражение | CTE / Common Table Expression | Named temporary result inside one SQL statement, defined with `WITH`. |
| представление | view | Named saved query used like a virtual table. |
| материализованное представление | materialized view | Database object that physically stores a query result. |
| условие / предикат | predicate | Boolean condition used in `WHERE`, `JOIN`, `CHECK`, partial indexes, and query planning. |

## Data Modeling

| RU | EN | Notes |
| --- | --- | --- |
| нормализация | normalization | Schema design approach that reduces duplication and update anomalies. |
| денормализация | denormalization | Intentional duplication or derived data storage for read or reporting needs. |
| связь один-к-одному | one-to-one relationship | Relationship where one row maps to at most one row on the other side. |
| связь один-ко-многим | one-to-many relationship | Relationship where one parent row can have many child rows. |
| связь многие-ко-многим | many-to-many relationship | Relationship modeled with a junction table in a relational database. |
| связующая таблица | junction table | Table that connects two sides of a many-to-many relationship. |
| мягкое удаление | soft delete | Marking a row as deleted instead of physically deleting it. |
| поля аудита | audit fields | Metadata columns such as `created_at`, `updated_at`, `created_by`, `updated_by`. |
| мультитенантность | multi-tenancy | Design where one system stores data for multiple tenants/customers. |

## Indexes And Storage

| RU | EN | Notes |
| --- | --- | --- |
| индекс | index | Auxiliary data structure used to speed up selected reads, ordering, joins, and uniqueness checks. |
| B-tree индекс | B-tree index | Default PostgreSQL index type for equality, ranges, ordering, and uniqueness. |
| последовательное сканирование | sequential scan | Reading table pages directly and checking rows without using an index. |
| сканирование по индексу | index scan | Reading matching index entries and then visiting heap rows when needed. |
| сканирование только по индексу | index-only scan | Scan that can return required columns from the index when visibility information allows it. |
| heap / куча таблицы | heap | PostgreSQL table storage where row versions are stored. |
| tuple / версия строки | tuple | Physical row version in PostgreSQL MVCC terminology. |
| страница | page | Fixed-size storage block used by tables and indexes. |
| корневая страница | root page | B-tree entry page used to start index navigation. |
| внутренняя страница | internal page | B-tree page that routes search to child pages. |
| листовая страница | leaf page | B-tree page that stores actual sorted index entries. |
| split страницы | page split | B-tree page split that happens when a page lacks room for a new entry. |
| составной индекс | composite index | Index over multiple columns where column order affects filtering and ordering. |
| правило левого префикса | leftmost prefix rule | Rule of thumb: composite B-tree indexes are most efficient when leading columns are constrained. |
| кардинальность | cardinality | Number of distinct values in a column or index key. |
| селективность | selectivity | Fraction of rows matched by a predicate. A smaller fraction means a more selective predicate. |
| перекос данных | data skew | Uneven value distribution that can make plans differ by parameter value. |
| частичный индекс | partial index | Index built only for rows that satisfy a `WHERE` predicate. |
| индекс по выражению | expression index | Index on a computed expression, for example `lower(email)`. |
| покрывающий индекс | covering index | Index that contains all columns needed by a query, enabling possible index-only scans. |
| включённые колонки | INCLUDE columns | PostgreSQL non-key payload columns stored in an index. |
| карта видимости | visibility map | PostgreSQL structure tracking all-visible/all-frozen heap pages; important for index-only scans. |
| класс операторов | operator class | Defines which operators an index supports for a data type. |
| раздувание индекса | index bloat | Wasted index space caused by updates, deletes, page splits, and maintenance lag. |
| HOT update | HOT update | PostgreSQL update that can avoid new index entries when indexed columns do not change. |
| журнал предзаписи | WAL / Write-Ahead Log | PostgreSQL durability and replication log; index maintenance increases WAL volume. |
