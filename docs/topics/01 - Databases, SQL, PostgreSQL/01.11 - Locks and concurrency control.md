# Locks and concurrency control

Target level: **Senior Java Backend Developer**.

English-first bilingual answers for PostgreSQL table locks, row locks, `SELECT FOR UPDATE`, `SKIP LOCKED`, advisory locks, deadlocks, timeouts, and blocked-query investigation.

</td>

<tr>
<th colspan="2" align="left">Short answer</th>

<p>Table-level locks are relation-level locks acquired by statements with different lock strengths.</p>

<td valign="top" width="50%">
<p>Обычный <code>SELECT</code> берёт слабый <code>ACCESS SHARE</code> lock. Многие schema-changing statements требуют сильных locks, а <code>ACCESS EXCLUSIVE</code> конфликтует с обычными reads и writes.</p>

<td valign="top" width="50%">
<p>Table-level locks используют conflict matrix. Это важно для migrations, <code>ALTER TABLE</code>, <code>CREATE INDEX</code>, <code>VACUUM FULL</code> и других maintenance operations.</p>

</tr>
<tr>

</td>
<td valign="top" width="50%">
<p>Быстрый DDL всё равно может быть опасен, если ждёт сильный lock и блокирует новые queries за собой. Используй lock timeouts и migration windows.</p>

<td valign="top" width="50%">
<ul><li>Blocked DDL может создать очередь blocked app queries.</li><li><code>VACUUM FULL</code> сильно disruptive.</li><li><code>CREATE INDEX CONCURRENTLY</code> уменьшает locks, но не устраняет их полностью.</li></ul>

<details>
<summary>🔥 <strong>DB-LOCK-004. What is SELECT FOR UPDATE?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Question</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>What is SELECT FOR UPDATE?</p>
</td>
<td valign="top" width="50%">
<p>Что такое SELECT FOR UPDATE?</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p><code>SELECT FOR UPDATE</code> reads rows and locks them as if they are going to be updated.</p>
</td>
<td valign="top" width="50%">
<p><code>SELECT FOR UPDATE</code> читает строки и блокирует их так, как будто они будут обновляться.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>It is a pessimistic locking tool. Other transactions trying to update, delete, or lock the same rows will wait until the current transaction ends.</p>
</td>
<td valign="top" width="50%">
<p>Это инструмент pessimistic locking. Другие транзакции, пытающиеся update, delete или lock те же строки, будут ждать завершения текущей транзакции.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Typical use: lock an order before changing its state.</p>
<pre><code class="language-sql">BEGIN;
SELECT * FROM orders WHERE id = 42 FOR UPDATE;
UPDATE orders SET status = &#x27;PAID&#x27; WHERE id = 42;
COMMIT;</code></pre>
</td>
<td valign="top" width="50%">
<p>Типичный use case: заблокировать заказ перед изменением его состояния.</p>
<pre><code class="language-sql">BEGIN;
SELECT * FROM orders WHERE id = 42 FOR UPDATE;
UPDATE orders SET status = &#x27;PAID&#x27; WHERE id = 42;
COMMIT;</code></pre>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Use it when concurrent modifications of the same business entity must be serialized. Keep the transaction short and consider <code>NOWAIT</code> or <code>lock_timeout</code> when waiting is unacceptable.</p>
</td>
<td valign="top" width="50%">
<p>Используй его, когда concurrent modifications одной business entity должны быть сериализованы. Держи транзакцию короткой и рассматривай <code>NOWAIT</code> или <code>lock_timeout</code>, если ждать нельзя.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul><li>Do not hold it across remote calls.</li><li>It only locks selected rows.</li><li>At higher isolation levels, locking a row changed after transaction start can fail.</li></ul>
</td>
<td valign="top" width="50%">
<ul><li>Не держи его во время remote calls.</li><li>Он блокирует только выбранные строки.</li><li>На более высоких isolation levels lock строки, изменённой после старта транзакции, может fail-иться.</li></ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: What does SELECT FOR UPDATE do?
A: Locks selected rows against conflicting modifications until transaction end.</p>
</td>
<td valign="top" width="50%">
<p>Q: Что делает SELECT FOR UPDATE?
A: Блокирует выбранные строки от conflicting modifications до конца транзакции.</p>
</td>
</tr>

<summary>🔥 <strong>DB-LOCK-006. What is SKIP LOCKED?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Question</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>What is SKIP LOCKED?</p>
</td>
<td valign="top" width="50%">
<p>Что такое SKIP LOCKED?</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p><code>SKIP LOCKED</code> skips locked rows instead of waiting for them.</p>
</td>
<td valign="top" width="50%">
<p><code>SKIP LOCKED</code> пропускает locked rows вместо ожидания.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>It is commonly used when many workers pull jobs from the same table. Each worker locks available rows and skips rows already locked by other workers.</p>
</td>
<td valign="top" width="50%">
<p>Его часто используют, когда много workers забирают jobs из одной таблицы. Каждый worker блокирует доступные строки и пропускает строки, уже залоченные другими workers.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Queue-like pattern:</p>
<pre><code class="language-sql">WITH picked AS (
  SELECT id
  FROM jobs
  WHERE status = &#x27;READY&#x27;
  ORDER BY created_at
  LIMIT 10
  FOR UPDATE SKIP LOCKED
)
UPDATE jobs j
SET status = &#x27;PROCESSING&#x27;
FROM picked
WHERE j.id = picked.id
RETURNING j.*;</code></pre>
</td>
<td valign="top" width="50%">
<p>Queue-like pattern:</p>
<pre><code class="language-sql">WITH picked AS (
  SELECT id
  FROM jobs
  WHERE status = &#x27;READY&#x27;
  ORDER BY created_at
  LIMIT 10
  FOR UPDATE SKIP LOCKED
)
UPDATE jobs j
SET status = &#x27;PROCESSING&#x27;
FROM picked
WHERE j.id = picked.id
RETURNING j.*;</code></pre>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>It improves throughput but gives an intentionally inconsistent view: locked rows disappear from the current worker’s result. You need retries, stuck-job recovery, and good indexes.</p>
</td>
<td valign="top" width="50%">
<p>Он повышает throughput, но даёт намеренно inconsistent view: locked rows исчезают из результата текущего worker. Нужны retries, stuck-job recovery и хорошие индексы.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul><li>Not a general correctness tool.</li><li>Can cause starvation.</li><li>Must be paired with job state and recovery logic.</li></ul>
</td>
<td valign="top" width="50%">
<ul><li>Не universal correctness tool.</li><li>Может вызвать starvation.</li><li>Нужно сочетать с job state и recovery logic.</li></ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: Typical use of SKIP LOCKED?
A: Concurrent workers claiming different rows without blocking.</p>
</td>
<td valign="top" width="50%">
<p>Q: Типичный use SKIP LOCKED?
A: Concurrent workers забирают разные строки без блокировки.</p>

</tr>
