<summary><strong>DB-MAINT-001. What is VACUUM in PostgreSQL?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Question</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>What is VACUUM in PostgreSQL?</p>
</td>
<td valign="top" width="50%">
<p>Что такое VACUUM в PostgreSQL?</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p><code>VACUUM</code> is PostgreSQL maintenance that cleans dead tuples, marks space reusable, updates visibility information, and helps prevent transaction ID wraparound.</p>
</td>
<td valign="top" width="50%">
<p><code>VACUUM</code> — maintenance PostgreSQL, который чистит dead tuples, помечает место reusable, обновляет visibility information и помогает предотвращать transaction ID wraparound.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Because MVCC keeps old tuple versions after <code>UPDATE</code> and <code>DELETE</code>, PostgreSQL needs VACUUM to remove versions that no transaction can see anymore.</p>
</td>
<td valign="top" width="50%">
<p>Поскольку MVCC сохраняет старые tuple versions после <code>UPDATE</code> и <code>DELETE</code>, PostgreSQL нужен VACUUM, чтобы удалять версии, которые больше не видит ни одна transaction.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Standard VACUUM usually does not shrink the physical file. It makes space reusable inside the relation and updates the visibility map.</p>
</td>
<td valign="top" width="50%">
<p>Обычный VACUUM обычно не уменьшает физический файл. Он делает место reusable внутри relation и обновляет visibility map.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>On busy OLTP tables, watch dead tuples, autovacuum activity, table bloat, transaction age, and tables where vacuum repeatedly fails to make progress.</p>
</td>
<td valign="top" width="50%">
<p>На busy OLTP tables следи за dead tuples, autovacuum activity, table bloat, transaction age и таблицами, где vacuum регулярно не продвигается.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul><li>Routine VACUUM is normal, not emergency cleanup.</li><li>VACUUM can be blocked by old snapshots.</li><li>VACUUM FULL is a different, disruptive operation.</li></ul>
</td>
<td valign="top" width="50%">
<ul><li>Routine VACUUM — нормальная операция, не emergency cleanup.</li><li>VACUUM может блокироваться old snapshots.</li><li>VACUUM FULL — другая, disruptive операция.</li></ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: What does VACUUM clean?
A: Dead tuple versions no transaction can see.</p>
</td>
<td valign="top" width="50%">
<p>Q: Что чистит VACUUM?
A: Dead tuple versions, которые не видит ни одна transaction.</p>
</td>
</tr>

<td valign="top" width="50%">

</td>
<td valign="top" width="50%">
<p>Зачем PostgreSQL нужен VACUUM?</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>PostgreSQL needs VACUUM because MVCC leaves old tuple versions behind after updates and deletes.</p>

<tr>
<th colspan="2" align="left">Interview answer</th>

</td>
<td valign="top" width="50%">
<p>VACUUM восстанавливает или переиспользует место, обновляет visibility map information, помогает index-only scans и защищает от transaction ID wraparound через freezing.</p>

<td valign="top" width="50%">
<p>VACUUM также может выполняться вместе с ANALYZE или сопровождаться autovacuum ANALYZE, чтобы держать planner statistics свежими.</p>

<tr>

<p>Если VACUUM не успевает, performance постепенно деградирует: читается больше pages, индексы bloat-ятся, cache efficiency падает, растёт wraparound risk.</p>

<tr>
<th colspan="2" align="left">Traps / caveats</th>

</td>
<td valign="top" width="50%">
<ul><li>VACUUM в PostgreSQL essential.</li><li>Autovacuum почти никогда нельзя отключать глобально.</li><li>Manual VACUUM не чинит плохой transaction design.</li></ul>
</td>

<tr>
<th colspan="2" align="left">Optional Anki</th>

<td valign="top" width="50%">
<p>Q: Назови две причины VACUUM.

<summary><strong>DB-MAINT-003. What is the difference between VACUUM and VACUUM FULL?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Question</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>What is the difference between VACUUM and VACUUM FULL?</p>
</td>
<td valign="top" width="50%">
<p>В чём разница между VACUUM и VACUUM FULL?</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Regular VACUUM marks dead-tuple space reusable; VACUUM FULL rewrites the table to physically reclaim disk space.</p>
</td>
<td valign="top" width="50%">
<p>Обычный VACUUM помечает место dead tuples reusable; VACUUM FULL переписывает таблицу, чтобы физически вернуть disk space.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p><code>VACUUM</code> can normally run with reads and writes. <code>VACUUM FULL</code> requires a strong exclusive lock and is much more disruptive.</p>
</td>
<td valign="top" width="50%">
<p><code>VACUUM</code> обычно может работать вместе с reads/writes. <code>VACUUM FULL</code> требует strong exclusive lock и гораздо более disruptive.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>VACUUM FULL creates a compact rewritten relation. This needs time, I/O, extra disk space during the operation, and usually a maintenance window.</p>
</td>
<td valign="top" width="50%">
<p>VACUUM FULL создаёт компактно переписанную relation. Для этого нужны time, I/O, extra disk space во время операции и обычно maintenance window.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>In production, prefer autovacuum tuning, partitioning, batched deletes, or online rebuild strategies before choosing VACUUM FULL.</p>
</td>
<td valign="top" width="50%">
<p>В production сначала рассматривай autovacuum tuning, partitioning, batched deletes или online rebuild strategies, прежде чем выбирать VACUUM FULL.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul><li>VACUUM FULL can cause downtime.</li><li>Regular VACUUM usually does not return disk to OS.</li><li>Frequent VACUUM FULL suggests root-cause problems.</li></ul>
</td>
<td valign="top" width="50%">
<ul><li>VACUUM FULL может вызвать downtime.</li><li>Regular VACUUM обычно не возвращает disk OS.</li><li>Частый VACUUM FULL говорит о root-cause problems.</li></ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: Which one physically shrinks table files?
A: VACUUM FULL.</p>
</td>
<td valign="top" width="50%">
<p>Q: Что физически уменьшает table files?
A: VACUUM FULL.</p>
</td>
</tr>
</tbody>

<summary>🔥 <strong>DB-MAINT-004. What is autovacuum?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Question</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>What is autovacuum?</p>
</td>
<td valign="top" width="50%">
<p>Что такое autovacuum?</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Autovacuum is PostgreSQL’s background system that automatically runs VACUUM and ANALYZE when tables need maintenance.</p>
</td>
<td valign="top" width="50%">
<p>Autovacuum — background-система PostgreSQL, которая автоматически запускает VACUUM и ANALYZE, когда таблицам нужен maintenance.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>It monitors table changes and starts workers based on thresholds for inserts, updates, deletes, and transaction ID age.</p>
</td>
<td valign="top" width="50%">
<p>Он отслеживает изменения таблиц и запускает workers по thresholds для inserts, updates, deletes и transaction ID age.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Important settings include autovacuum thresholds, scale factors, cost delay/limit, max workers, and per-table storage parameters.</p>
</td>
<td valign="top" width="50%">
<p>Важные settings: autovacuum thresholds, scale factors, cost delay/limit, max workers и per-table storage parameters.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Large or hot tables often need table-specific autovacuum tuning because default scale factors may trigger too late.</p>
</td>
<td valign="top" width="50%">
<p>Large или hot tables часто требуют table-specific autovacuum tuning, потому что default scale factors могут срабатывать слишком поздно.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul><li>Autovacuum can be running but still insufficient.</li><li>Long transactions can prevent useful cleanup.</li><li>Too aggressive autovacuum can create I/O pressure.</li></ul>
</td>
<td valign="top" width="50%">
<ul><li>Autovacuum может работать, но всё равно быть insufficient.</li><li>Долгие transactions могут мешать useful cleanup.</li><li>Слишком aggressive autovacuum может создать I/O pressure.</li></ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: What does autovacuum automate?
A: VACUUM and ANALYZE, including anti-wraparound maintenance.</p>
</td>
<td valign="top" width="50%">
<p>Q: Что автоматизирует autovacuum?
A: VACUUM и ANALYZE, включая anti-wraparound maintenance.</p>
</td>
</tr>
</tbody>
</table>

<td valign="top" width="50%">
<p>What can happen if autovacuum does not keep up?</p>
</td>
<td valign="top" width="50%">
<p>Что произойдёт, если autovacuum не успевает?</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>

</tr>

<th colspan="2" align="left">Interview answer</th>

</td>
<td valign="top" width="50%">
<p>Симптомы часто появляются постепенно: выше I/O, больше indexes, ниже cache efficiency, медленнее scans, нестабильная latency и больше heap fetches для index-only scans.</p>

<td valign="top" width="50%">
<p>Autovacuum может не успевать из-за долгих transactions, слишком conservative thresholds, малого числа workers, heavy update/delete workload или replication slots, удерживающих old horizons.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Investigate per-table dead tuples, last autovacuum time, autovacuum logs, table age, long-running transactions, and write rate.</p>
</td>
<td valign="top" width="50%">
<p>Расследуй per-table dead tuples, last autovacuum time, autovacuum logs, table age, long-running transactions и write rate.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul><li>One manual VACUUM may not fix the root cause.</li><li>A single hot table can need custom settings.</li><li>Ignoring wraparound pressure can become an outage.</li></ul>
</td>
<td valign="top" width="50%">
<ul><li>Один manual VACUUM может не исправить root cause.</li><li>Одна hot table может требовать custom settings.</li><li>Игнорирование wraparound pressure может стать outage.</li></ul>

<th colspan="2" align="left">Optional Anki</th>

<table>
<tbody>
<tr>

<tr>
<td valign="top" width="50%">
<p>What is table bloat?</p>

</td>
</tr>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Table bloat is wasted space inside a table caused by dead/reusable tuples and page fragmentation.</p>
</td>
<td valign="top" width="50%">
<p>Table bloat — wasted space внутри таблицы из-за dead/reusable tuples и page fragmentation.</p>

</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>

<p>After many updates/deletes, a table file can contain many pages with little live data. Regular VACUUM can reuse space but usually does not shrink the file.</p>
</td>
<td valign="top" width="50%">
<p>После многих updates/deletes table file может содержать много pages с малым объёмом live data. Regular VACUUM может переиспользовать место, но обычно не shrink-ит файл.</p>

<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>

<td valign="top" width="50%">
<p>Bloat hurts cache efficiency and makes scans read more pages for the same useful data.</p>
</td>
<td valign="top" width="50%">
<p>Bloat ухудшает cache efficiency и заставляет scans читать больше pages для тех же useful data.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Reduce it with autovacuum tuning, shorter transactions, batching, partition lifecycle management, fillfactor, and avoiding unnecessary updates.</p>
</td>
<td valign="top" width="50%">
<p>Снижай его через autovacuum tuning, shorter transactions, batching, partition lifecycle management, fillfactor и избегание unnecessary updates.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul><li>A large table is not necessarily bloated.</li><li>VACUUM FULL reclaims disk but locks heavily.</li><li>Partition drop/detach is often better for old-data cleanup.</li></ul>
</td>
<td valign="top" width="50%">
<ul><li>Большая таблица не обязательно bloated.</li><li>VACUUM FULL возвращает disk, но сильно locks.</li><li>Partition drop/detach часто лучше для old-data cleanup.</li></ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>

<th colspan="2" align="left">Question</th>

<tr>
<td valign="top" width="50%">

<td valign="top" width="50%">
<p>Что такое index bloat?</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Short answer</th>

</tr>

<td valign="top" width="50%">
<p>Updates и deletes могут оставлять obsolete index entries, указывающие на old tuple versions. Vacuum может чистить часть этого, но indexes всё равно могут неэффективно расти.</p>

<th colspan="2" align="left">Deep dive</th>

</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">

</td>
<td valign="top" width="50%">
<p>Используй <code>REINDEX CONCURRENTLY</code> для production rebuilds при необходимости, но также чини workload, indexes и autovacuum behavior, которые вызвали bloat.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
