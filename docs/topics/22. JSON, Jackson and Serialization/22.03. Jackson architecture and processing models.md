# Jackson architecture and processing models

---

<a id="json-jack-001"></a>

<details>
<summary><strong>JSON-JACK-001. What problems does Jackson solve in Java backend applications?</strong></summary>

#### Short answer

Jackson maps between Java objects and JSON, handles parsing/generation, annotations, modules, custom types and framework integration.

#### Interview answer

In Java backend services, Jackson is commonly used to deserialize HTTP request bodies into DTOs and serialize responses back to JSON. It also supports events, config files, clients, tests and custom formats.

It handles property discovery, constructors, records, Java Time modules, custom serializers, tree model and streaming APIs.

#### Deep dive

Jackson is not only an object mapper. It has three common models: data binding, tree model and streaming parser/generator. Choosing the right model matters for correctness and performance.

#### Production angle

Most JSON behavior in a Spring Boot service comes from central Jackson configuration, so inconsistent mappers can cause subtle API bugs.

#### Traps / caveats

- Jackson binding does not replace validation.
- Defaults may be too permissive for public APIs.
- Different clients may accidentally use different mapper configuration.

#### Optional Anki

Q: What does Jackson mainly do?
A: Maps JSON to Java objects and Java objects to JSON.

</details>

<a id="json-jack-002"></a>

<details>
<summary><strong>JSON-JACK-002. What is `ObjectMapper` / `JsonMapper`, and why should it usually be shared and configured centrally?</strong></summary>

#### Short answer

`ObjectMapper` is Jackson's main configured mapper; it should usually be reused because configuration is expensive and must be consistent.

#### Interview answer

An `ObjectMapper` knows how to parse, generate, serialize and deserialize using registered modules, naming strategies, inclusion rules and feature flags. Creating many ad hoc mappers leads to inconsistent JSON behavior and wastes caches.

In Spring Boot, prefer central configuration through Boot customizers or a shared bean.

#### Deep dive

Mappers are thread-safe for normal read/write operations after configuration. Mutating configuration at request time is unsafe because cached serializers and concurrent requests may observe inconsistent behavior.

#### Production angle

A common incident is one endpoint or HTTP client using a different date format, unknown-field policy or enum setting from the rest of the service.

#### Traps / caveats

- Configure before use.
- Do not mutate the shared mapper per request.
- Use `ObjectReader` or `ObjectWriter` for immutable per-use variants.

#### Optional Anki

Q: Should `ObjectMapper` usually be reused?
A: Yes, configure it centrally and reuse it.

</details>

<a id="json-jack-003"></a>

<details>
<summary><strong>JSON-JACK-003. What is Jackson data binding?</strong></summary>

#### Short answer

Data binding maps JSON directly to Java types such as DTOs, records, collections and maps.

#### Interview answer

With data binding, Jackson reads JSON and constructs Java objects based on the target type, property names, constructors, setters, fields and annotations. It can also serialize those Java objects back into JSON.

This is the normal model for REST request and response DTOs.

#### Deep dive

Data binding is convenient but assumes the JSON shape matches a known Java type. It can fail on missing constructors, unknown fields, generic erasure, unsupported Java Time types or conflicting annotations.

#### Production angle

Use DTOs that deliberately model the API contract, not domain entities or arbitrary `Object` graphs.

#### Traps / caveats

- Binding success does not mean validation success.
- Raw generic types deserialize poorly.
- Binding large payloads can allocate many objects.

#### Optional Anki

Q: What is Jackson data binding?
A: Direct mapping between JSON and Java values.

</details>

<a id="json-jack-004"></a>

<details>
<summary><strong>JSON-JACK-004. What is the Jackson Tree Model with `JsonNode`, `ObjectNode` and `ArrayNode`?</strong></summary>

#### Short answer

The Tree Model represents JSON as an in-memory node tree instead of binding it directly to a DTO.

#### Interview answer

`JsonNode` is the base type for JSON tree nodes. `ObjectNode` represents JSON objects and `ArrayNode` represents arrays. It is useful when the shape is partly dynamic, when only a few fields need inspection, or when transforming JSON generically.

It sits between full data binding and low-level streaming.

#### Deep dive

Tree processing keeps the whole payload in memory. It is flexible but less type-safe than DTO binding.

#### Production angle

Use it for dynamic integrations, webhooks or partial transformations, but avoid making core business logic operate on untyped trees forever.

#### Traps / caveats

- Missing fields may return special missing nodes or null depending on access method.
- Type errors appear later than with DTOs.
- Large trees can consume significant memory.

#### Optional Anki

Q: When is `JsonNode` useful?
A: When JSON shape is dynamic or only partial inspection is needed.

</details>

<a id="json-jack-005"></a>

<details>
<summary><strong>JSON-JACK-005. What is the Jackson Streaming API?</strong></summary>

#### Short answer

The Streaming API reads and writes JSON token by token with low memory overhead.

#### Interview answer

Jackson's streaming parser reads tokens like start object, field name, string value and end array. The generator writes tokens similarly. This avoids building a full object graph or `JsonNode` tree.

It is appropriate for very large arrays, exports, imports and high-throughput processing.

#### Deep dive

Streaming gives more control but more responsibility. You must manage token order, validation and error handling yourself.

#### Production angle

It prevents memory spikes when processing large files or responses that cannot fit comfortably in heap.

#### Traps / caveats

- Streaming code is harder to read and test.
- You still need size and depth limits for untrusted input.
- Do not prematurely use it for small DTO payloads.

#### Optional Anki

Q: Main benefit of Jackson streaming?
A: Processing large JSON incrementally with low memory use.

</details>

<a id="json-jack-006"></a>

<details>
<summary><strong>JSON-JACK-006. When would you deserialize JSON into a DTO, a `Map`, or a `JsonNode`?</strong></summary>

#### Short answer

Use DTOs for known contracts, `JsonNode` for dynamic or partial JSON, and `Map` for simple unstructured key-value data.

#### Interview answer

For REST APIs, DTOs are usually best because they are typed, validated and documented. `JsonNode` is useful when the shape is dynamic or when forwarding/transformation is needed. A `Map` can work for simple metadata or flexible attributes, but it loses type safety quickly.

#### Deep dive

Binding to `Map<String, Object>` often produces nested maps, lists and boxed values. Business code then becomes full of casts and runtime assumptions.

#### Production angle

Typed DTOs make contracts clearer and reduce runtime failures. Dynamic models need extra validation and authorization review.

#### Traps / caveats

- Avoid `Object` graphs for untrusted input.
- `Map` does not validate field names or types.
- Dynamic fields can bypass authorization if not reviewed carefully.

#### Optional Anki

Q: Best default for known API payloads?
A: A purpose-built DTO.

</details>

<a id="json-jack-007"></a>

<details>
<summary><strong>JSON-JACK-007. What are `ObjectReader` and `ObjectWriter`, and when are they useful?</strong></summary>

#### Short answer

They are immutable, reusable read/write configurations derived from an `ObjectMapper`.

#### Interview answer

`ObjectReader` and `ObjectWriter` let you preconfigure a target type, pretty printing, views or other per-use settings without mutating the shared mapper. They are thread-safe and can be reused.

They are useful for hot paths, repeated generic types or endpoint-specific serialization behavior.

#### Deep dive

They also help avoid ad hoc mapper copies. A reader for `List<UserDto>` can hold the resolved target type once.

#### Production angle

Use them when a service repeatedly reads or writes the same payload shape or needs a specific immutable configuration.

#### Traps / caveats

- They do not replace central mapper configuration.
- Do not create them to hide inconsistent API behavior.
- Benchmark before treating them as a major performance optimization.

#### Optional Anki

Q: Why use `ObjectReader`?
A: To reuse an immutable read configuration, often with a fixed target type.

</details>

<a id="json-jack-008"></a>

<details>
<summary><strong>JSON-JACK-008. What are Jackson modules, and why are they commonly registered with the mapper?</strong></summary>

#### Short answer

Modules extend Jackson with support for additional types, serializers, deserializers and behavior.

#### Interview answer

Jackson modules plug into the mapper. Common examples include Java Time support, JDK 8 types, parameter names, Kotlin support or performance modules. Without the right module, types like `LocalDate` or `Instant` may serialize incorrectly or fail.

Spring Boot auto-registers many modules from the classpath.

#### Deep dive

Modules can provide serializers, deserializers, type modifiers and annotation introspection. Registration order can matter in advanced cases.

#### Production angle

Verify mapper modules in tests, especially after framework upgrades or adding custom mappers.

#### Traps / caveats

- A manually defined mapper can lose Boot's auto-registered modules.
- Different mappers may serialize dates differently.
- Modules are configuration, not domain validation.

#### Optional Anki

Q: Why register the Java Time module?
A: To handle Java Time types such as `LocalDate` and `Instant` correctly.

</details>

<a id="json-jack-009"></a>

<details>
<summary><strong>JSON-JACK-009. How does Jackson discover properties from fields, getters, setters, constructors and records?</strong></summary>

#### Short answer

Jackson discovers logical properties from visible accessors, fields, creator parameters, annotations and record components according to mapper configuration.

#### Interview answer

For serialization, Jackson commonly uses getters, fields or record accessors. For deserialization, it may use a default constructor plus setters/fields, a creator constructor/factory, builder methods or a record canonical constructor.

Annotations such as `@JsonProperty`, visibility settings and naming strategies can change the property names and access.

#### Deep dive

A logical JSON property may combine a field, getter, setter and constructor parameter. Conflicting names or annotations can lead to surprising behavior.

#### Production angle

Property discovery issues often appear after Lombok changes, record migrations, refactors or visibility changes.

#### Traps / caveats

- Getter names can define JSON fields.
- Constructor parameter names may need metadata or annotations in some cases.
- Renaming Java members can break JSON contracts.

#### Optional Anki

Q: What is a Jackson logical property?
A: The JSON property Jackson builds from fields, accessors, creators and annotations.

</details>

<details>
<summary><strong>JSON-JACK-010. Why is mutating a shared Jackson mapper at request time dangerous?</strong></summary>

#### Short answer

It can create inconsistent behavior across concurrent requests and invalidate assumptions in Jackson's caches.

#### Interview answer

`ObjectMapper` is safe to reuse after configuration, but changing features, modules or serializers dynamically while requests are using it can produce unpredictable results. Some requests may see old behavior and others new behavior.

Use immutable `ObjectReader`, `ObjectWriter` or separate configured mappers for genuinely different policies.

#### Deep dive

Jackson caches serializers and deserializers based on type and configuration. Runtime mutation can interact badly with those caches.

#### Production angle

Request-specific JSON behavior should be explicit and tested, not achieved by toggling global mapper features.

#### Traps / caveats

- Do not call global configuration methods inside controllers.
- Mapper copies can also drift if overused.
- Prefer central configuration plus per-use readers/writers.

#### Optional Anki

Q: When is `ObjectMapper` thread-safe?
A: For normal use after it has been fully configured.

</details>

<a id="json-jack-011"></a>

<details>
<summary><strong>JSON-JACK-011. How does Jackson cache serializers and deserializers, and why can that affect performance?</strong></summary>

#### Short answer

Jackson resolves serializers/deserializers and caches them, so reused mappers avoid repeated introspection and setup work.

#### Interview answer

When Jackson first handles a type, it introspects properties, annotations, constructors and modules to build serializers or deserializers. Reusing a configured mapper lets later calls reuse cached work.

Creating new mappers repeatedly loses this benefit and can increase CPU and allocation.

#### Deep dive

Cache behavior is one reason mapper configuration should be stable. Different declared types, polymorphic typing or generic type tokens can lead to different resolved serializers.

#### Production angle

In high-throughput services, mapper reuse and stable DTO types can reduce serialization overhead.

#### Traps / caveats

- Do not optimize blindly; measure first.
- Dynamic shapes and many types can still create overhead.
- Runtime mapper mutation can make cache behavior hard to reason about.

#### Optional Anki

Q: Why reuse `ObjectMapper` for performance?
A: It reuses resolved serializers, deserializers and configuration caches.

</details>

<a id="json-jack-012"></a>

<details>
<summary><strong>JSON-JACK-012. How are serializers and deserializers selected when annotations, modules and declared types all apply?</strong></summary>

#### Short answer

Jackson combines declared target type, runtime type, annotations, registered modules, custom handlers and mapper features to choose handlers.

#### Interview answer

For serialization, Jackson starts from the declared and runtime type, inspects annotations and checks registered serializers from modules or custom configuration. For deserialization, the declared target type is especially important because JSON itself does not carry Java type information unless configured.

Annotations close to the property can override broader configuration.

#### Deep dive

Selection becomes more complex with polymorphism, generics, custom modules, mix-ins and `@JsonSerialize` or `@JsonDeserialize`.

#### Production angle

When behavior is surprising, inspect the declared field type, annotations, mapper modules and whether a custom serializer is registered globally.

#### Traps / caveats

- Declared type can hide runtime subtype properties.
- Raw `Object` targets are dangerous for untrusted JSON.
- Custom serializers can affect more endpoints than intended.

#### Optional Anki

Q: Why does declared target type matter during deserialization?
A: JSON does not normally contain Java type metadata.

</details>
