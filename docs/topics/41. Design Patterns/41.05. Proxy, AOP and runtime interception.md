# 41.05. Proxy, AOP and runtime interception

---

<a id="dp-proxy-001"></a>

<details>
<summary><strong>DP-PROXY-001. What is the Proxy pattern?</strong></summary>

#### Short answer

Proxy provides a stand-in object that controls access to another object.

#### Interview answer

A proxy exposes the same interface as the target but adds behavior before, after or instead of the target call. It can enforce security, lazy loading, caching, remote access, transaction boundaries, metrics or validation.

The key intent is access control or interception, not just code reuse.

#### Deep dive

Proxy is common in Java frameworks. Spring AOP proxies, JPA lazy proxies and dynamic proxies all use the idea of standing between the caller and the real object.

#### Production angle

Proxy behavior can be invisible at the call site, so it is powerful but can complicate debugging.

#### Traps / caveats

- Proxy does not change calls that bypass the proxy.
- Runtime type may not be the target class.
- Hidden interception can surprise tests and logs.

#### Optional Anki

Q: Proxy pattern intent?
A: Control access to a target object through a stand-in object.

</details>

<a id="dp-proxy-002"></a>

<details>
<summary><strong>DP-PROXY-002. What is the difference between static proxy and dynamic proxy?</strong></summary>

#### Short answer

A static proxy is written explicitly; a dynamic proxy is generated at runtime.

#### Interview answer

With a static proxy, you write a class such as `LoggingPaymentGateway` that implements `PaymentGateway` and delegates to a target. With a dynamic proxy, Java or a framework generates a proxy class at runtime and routes calls through an invocation handler or interceptor.

Static proxies are explicit and readable. Dynamic proxies reduce boilerplate for cross-cutting infrastructure.

#### Deep dive

Dynamic proxy mechanisms include JDK interface proxies and class-based proxying through bytecode generation.

#### Production angle

Static proxies are easier to debug for business-specific behavior. Dynamic proxies are common for transactions, security and framework features.

#### Traps / caveats

- Dynamic proxies can hide behavior from simple code navigation.
- Static proxies can create repetitive wrappers.
- Generated proxies may affect casting and annotation lookup.

#### Optional Anki

Q: Static vs dynamic proxy?
A: Static proxy is hand-written; dynamic proxy is generated at runtime.

</details>

<a id="dp-proxy-003"></a>

<details>
<summary><strong>DP-PROXY-003. How does Java dynamic proxy work?</strong></summary>

#### Short answer

JDK dynamic proxy creates a runtime class that implements interfaces and dispatches method calls to an `InvocationHandler`.

#### Interview answer

You provide interfaces, a classloader and an invocation handler. Java creates a proxy object implementing those interfaces. When a method is called, the proxy calls `handler.invoke(proxy, method, args)`, and the handler decides what to do.

The handler can delegate to a real target, check security, log, retry or return a value directly.

#### Deep dive

JDK dynamic proxies work with interfaces. They do not subclass concrete classes. Class-based proxying needs another mechanism.

#### Production angle

Dynamic proxies are useful for infrastructure and framework code, but most application code should not need to create them manually.

#### Traps / caveats

- Only interface methods are proxied by JDK dynamic proxy.
- Reflection-based dispatch has debugging and performance considerations.
- Be careful with `equals()`, `hashCode()` and `toString()`.

#### Optional Anki

Q: JDK dynamic proxy dispatches calls to what?
A: An `InvocationHandler`.

</details>

<a id="dp-proxy-004"></a>

<details>
<summary><strong>DP-PROXY-004. What is `InvocationHandler` in Java?</strong></summary>

#### Short answer

`InvocationHandler` is the callback interface that receives method calls made on a JDK dynamic proxy.

#### Interview answer

Its `invoke()` method receives the proxy object, the reflected `Method`, and arguments. The handler can perform logic before and after calling the real target, or decide not to call the target.

It is the core interception point for JDK dynamic proxies.

#### Deep dive

Handlers must preserve method contracts. Returning the wrong type, swallowing exceptions or mishandling `Object` methods can break clients.

#### Production angle

Frameworks use similar concepts for transactions, RPC clients, validation and metrics. In application code, explicit wrappers are often clearer.

#### Traps / caveats

- Handle `equals()`, `hashCode()` and `toString()` deliberately.
- Preserve checked and runtime exception semantics.
- Avoid putting large business workflows inside generic handlers.

#### Optional Anki

Q: What method does `InvocationHandler` define?
A: `invoke(Object proxy, Method method, Object[] args)`.

</details>

<a id="dp-proxy-005"></a>

<details>
<summary><strong>DP-PROXY-005. What limitations do JDK dynamic proxies have?</strong></summary>

#### Short answer

JDK dynamic proxies proxy interfaces, not concrete class methods.

#### Interview answer

A JDK dynamic proxy can implement interfaces and intercept calls through those interface methods. It cannot proxy final classes, concrete methods not exposed through an interface, constructors or private methods.

If a caller casts to the concrete implementation, a JDK proxy may fail.

#### Deep dive

Class-based proxies solve some interface limitations by subclassing, but they have their own limits around final classes and final methods.

#### Production angle

Proxy type affects Spring AOP, tests, casting, annotation placement and runtime diagnostics.

#### Traps / caveats

- Interface-based injection works better with JDK proxies.
- Concrete-class assumptions can break after proxying.
- Calls must go through the proxy instance.

#### Optional Anki

Q: Main JDK dynamic proxy limitation?
A: It proxies interfaces, not arbitrary concrete class methods.

</details>

<a id="dp-proxy-006"></a>

<details>
<summary><strong>DP-PROXY-006. How is class-based proxying different from JDK interface proxying?</strong></summary>

#### Short answer

Class-based proxying creates a subclass of the target class; JDK proxying creates an object implementing interfaces.

#### Interview answer

Class-based proxies can intercept calls to overridable methods on a concrete class. They are useful when no interface is available. JDK proxies only expose interface methods.

Class-based proxies cannot override final methods, and final classes cannot be subclassed.

#### Deep dive

Spring commonly uses class-based proxying through bytecode generation mechanisms when configured or when interface proxying is not suitable.

#### Production angle

The proxy mechanism can affect `bean.getClass()`, annotations, method visibility, equality and casts.

#### Traps / caveats

- Private methods are not intercepted by normal proxy-based AOP.
- Final methods are a common source of missing advice.
- Constructor logic is not the normal interception point.

#### Optional Anki

Q: Class-based proxy limitation?
A: It cannot intercept final methods because it relies on subclassing and overriding.

</details>

<a id="dp-proxy-007"></a>

<details>
<summary><strong>DP-PROXY-007. How does Spring use proxies for AOP, transactions, caching and security?</strong></summary>

#### Short answer

Spring often wraps beans in proxies so method calls can run advice such as transactions, caching, security or async behavior.

#### Interview answer

For `@Transactional`, the proxy opens or joins a transaction before invoking the target method and commits or rolls back afterward. For `@Cacheable`, it checks the cache around the call. For method security, it checks authorization before access.

The common rule is that the call must go through the Spring proxy.

#### Deep dive

Spring may use JDK dynamic proxies or class-based proxies. Multiple framework features can be combined in one interceptor chain.

#### Production angle

Many "annotation does not work" incidents are actually proxy-call-path incidents.

#### Traps / caveats

- Self-invocation bypasses the proxy.
- Objects created with `new` are not Spring-proxied.
- Proxy advice ordering can matter.

#### Optional Anki

Q: What must happen for Spring proxy advice to apply?
A: The method call must go through the Spring proxy.

</details>

<a id="dp-proxy-008"></a>

<details>
<summary><strong>DP-PROXY-008. Why can Spring `@Transactional` fail on self-invocation?</strong></summary>

#### Short answer

Self-invocation calls `this.method()` inside the target object, bypassing the Spring proxy where transaction advice lives.

#### Interview answer

Spring proxy-based transactions apply when another bean calls the transactional method through the proxy. If a method in the same class calls another annotated method using `this`, the call does not leave the target object, so the proxy cannot intercept it.

The annotation may be present, but the call path is wrong.

#### Deep dive

Common fixes are moving the transactional method to another bean, calling through a properly injected proxy, or redesigning transaction boundaries. `AopContext.currentProxy()` exists but couples business code to AOP details.

#### Production angle

This can cause missing rollbacks, lazy loading failures, partial writes or code running outside the expected transaction.

#### Traps / caveats

- Making the method public is not enough if it is still called internally.
- Tests that instantiate the class directly miss proxy behavior.
- Private methods cannot be transactional through proxy AOP.

#### Optional Anki

Q: Why does self-invocation skip `@Transactional`?
A: The call uses `this`, not the Spring proxy.

</details>

<a id="dp-proxy-009"></a>

<details>
<summary><strong>🧠 DP-PROXY-009. How can proxy-based design affect `equals()`, `hashCode()`, final methods and runtime type checks?</strong></summary>

#### Short answer

Proxies can change the runtime class, expose only interfaces, and fail to intercept final methods, so naive type and equality assumptions can break.

#### Interview answer

If code uses exact `getClass()` checks, a proxy subclass may not compare equal to the real class. A JDK proxy may not be castable to the implementation class. Class-based proxies cannot override final methods, so advice may not apply.

This is especially relevant with JPA entities and Spring beans.

#### Deep dive

`equals()`, `hashCode()` and `toString()` should be designed carefully when proxies are expected. Logging or equality checks should not accidentally trigger lazy loading or expensive work.

#### Production angle

Proxy-related equality bugs appear in sets, caches, security principals, persistence contexts and tests.

#### Traps / caveats

- Do not rely on concrete runtime classes when interfaces are enough.
- Avoid final methods for advised behavior.
- Do not put mutable proxied objects into hash-based collections carelessly.

#### Optional Anki

Q: Why can exact class equality checks fail with proxies?
A: The runtime object may be a proxy class, not the target class.

</details>

<a id="dp-proxy-010"></a>

<details>
<summary><strong>DP-PROXY-010. When is proxy-based interception a bad fit?</strong></summary>

#### Short answer

It is a bad fit when behavior should be explicit, business-specific, highly ordered, or applied inside hot local code paths.

#### Interview answer

Proxy interception is good for uniform cross-cutting concerns. It is less good for core business workflow where readers need to see decisions directly. Hidden interception can make debugging, testing and reasoning harder.

For example, explicit decorators may be clearer for provider-specific retry behavior than a broad retry aspect.

#### Deep dive

Proxy-based code also struggles with self-invocation, final/private methods, manual object creation and non-Spring-managed objects.

#### Production angle

During incidents, hidden behavior increases diagnostic cost. Keep proxy use focused and observable.

#### Traps / caveats

- Do not use AOP to hide business rules.
- Avoid broad pointcuts that affect unrelated code.
- Test behavior through the same call path production uses.

#### Optional Anki

Q: Best use case for proxy-based interception?
A: Uniform infrastructure concerns such as transactions, security, caching and metrics.

</details>
