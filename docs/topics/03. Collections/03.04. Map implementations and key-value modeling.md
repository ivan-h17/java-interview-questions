# 03.04. Map implementations and key-value modeling

---

<a id="col-map-001"></a>

<details>
<summary><strong>COL-MAP-001. What is a `Map`?</strong></summary>

#### Short answer

A `Map` stores key-value mappings where each key maps to at most one value.

#### Interview answer

`Map<K,V>` is used when data should be found by key: user by ID, configuration by name, count by category, cache value by request key. Keys are unique; values may repeat. Common operations are `put`, `get`, `remove`, `containsKey` and iteration through key, value or entry views.

#### Deep dive

`Map` is not a `Collection`, but its views are collections: `keySet()`, `values()` and `entrySet()`. Different implementations provide different ordering, lookup and concurrency guarantees.

#### Production angle

Maps are everywhere in backend code: caches, indexes, grouping results, deduplication by business key and DTO assembly. They are powerful, but overusing generic maps can hide missing domain types.

#### Traps / caveats

- Keys must be stable for hash or sorted maps.
- `get()` returning null can mean absent or mapped to null for maps that allow null values.
- `Map` iteration order depends on implementation.

#### Optional Anki

Q: Are map keys unique?
A: Yes. Values may repeat.

</details>

<a id="col-map-002"></a>

<details>
<summary><strong>COL-MAP-002. What is the difference between `HashMap`, `LinkedHashMap` and `TreeMap`?</strong></summary>

#### Short answer

`HashMap` is unordered and hash-based, `LinkedHashMap` is hash-based with predictable iteration order, and `TreeMap` is sorted by key.

#### Interview answer

Use `HashMap` for normal key lookup when order does not matter. Use `LinkedHashMap` when iteration order matters, especially insertion order or access order. Use `TreeMap` when keys must be sorted or range queries are needed.

#### Deep dive

`HashMap` and `LinkedHashMap` use `equals()` and `hashCode()` for keys. `TreeMap` uses `Comparable` or `Comparator`. `TreeMap` operations are typically `O(log n)`, while hash maps are average `O(1)` for basic lookup.

#### Production angle

API response order, deterministic tests and cache eviction are common reasons to prefer `LinkedHashMap` over `HashMap`.

#### Traps / caveats

- `HashMap` order must not be relied on.
- `TreeMap` can treat distinct keys as the same if comparison returns zero.
- `LinkedHashMap` still needs stable `equals()` and `hashCode()`.

#### Optional Anki

Q: Which map supports sorted key ranges?
A: `TreeMap`.

</details>

<a id="col-map-003"></a>

<details>
<summary><strong>🧠 COL-MAP-003. When should you use `TreeMap` or `NavigableMap`?</strong></summary>

#### Short answer

Use them when you need sorted keys, range views or nearest-key operations.

#### Interview answer

`TreeMap` implements `NavigableMap`, so it can answer questions such as "first key after this value", "floor key", "all entries between A and B" or "iterate keys in sorted order." This is different from a `HashMap`, which is optimized for direct lookup but has no sorted navigation.

#### Deep dive

Typical operations include `lowerKey`, `floorKey`, `ceilingKey`, `higherKey`, `subMap`, `headMap`, `tailMap`, `firstEntry` and `lastEntry`. Keys must be comparable or a comparator must be supplied.

#### Production angle

Useful examples include time buckets, thresholds, prefix-like ranges when modeled carefully, sorted schedules and in-memory lookup tables. For large persistent data, use database indexes instead.

#### Traps / caveats

- It is not faster than `HashMap` for simple lookup.
- Comparator consistency is critical.
- It is not thread-safe by default.

#### Optional Anki

Q: What does `NavigableMap` add?
A: Nearest-key and range navigation operations.

</details>

<a id="col-map-004"></a>

<details>
<summary><strong>COL-MAP-004. What is `LinkedHashMap`, and how can it implement simple LRU behavior?</strong></summary>

#### Short answer

`LinkedHashMap` is a hash map with linked iteration order; in access-order mode plus `removeEldestEntry`, it can implement a simple LRU map.

#### Interview answer

By default, `LinkedHashMap` iterates in insertion order. It can also be constructed in access-order mode, where reads and writes move entries toward the end. Overriding `removeEldestEntry` lets a subclass evict the oldest entry when size exceeds a limit.

#### Deep dive

This is enough for simple in-process LRU behavior, but it is not a full cache. It lacks expiration policies, weight-based eviction, metrics, refresh, async loading and built-in concurrency controls.

#### Production angle

For serious caching, prefer a cache library such as Caffeine. Use `LinkedHashMap` LRU only for small local utilities or interview-level examples.

#### Traps / caveats

- It is not thread-safe.
- Size-based eviction is not memory-aware.
- It does not handle TTL, refresh or distributed invalidation.

#### Optional Anki

Q: Which `LinkedHashMap` mode supports LRU-like order?
A: Access-order mode.

</details>

<a id="col-map-005"></a>

<details>
<summary><strong>🧠 COL-MAP-005. What is `IdentityHashMap`, and when is identity-based lookup useful?</strong></summary>

#### Short answer

`IdentityHashMap` compares keys by `==` instead of `equals()`.

#### Interview answer

It is a special-purpose map for cases where object identity matters more than logical equality. Examples include object graph traversal, serialization internals, proxy tracking or cycle detection where two equal objects must still be treated as different instances.

#### Deep dive

Because it uses reference identity, two distinct `String` objects with the same text can be separate keys. This intentionally violates normal `Map` expectations around logical equality, so it should be used rarely and clearly.

#### Production angle

It is useful in infrastructure code, not ordinary business maps. In business logic, identity-based lookup often hides a modeling problem.

#### Traps / caveats

- It does not use `equals()`.
- It can surprise maintainers and tests.
- Do not use it as a faster `HashMap`.

#### Optional Anki

Q: What equality does `IdentityHashMap` use?
A: Reference identity with `==`.

</details>

<a id="col-map-006"></a>

<details>
<summary><strong>🧠 COL-MAP-006. What is `EnumMap`, and why is it efficient?</strong></summary>

#### Short answer

`EnumMap` is a specialized map whose keys are enum constants, usually stored in an array indexed by enum ordinal internally.

#### Interview answer

Because the key universe is fixed and known, `EnumMap` can be compact and fast compared with `HashMap<Enum, V>`. It also preserves enum declaration order during iteration.

#### Deep dive

`EnumMap` requires all keys to be from one enum type. It does not permit null keys, though values may be null. It is a good fit for mapping statuses to handlers, enum flags to configuration, or enum states to display values.

#### Production angle

`EnumMap` communicates intent and avoids hash overhead for enum-keyed lookups. It is often cleaner than switch statements when behavior or data is table-like.

#### Traps / caveats

- It only works with enum keys.
- Enum ordinal should not be used as persisted business data.
- It is not synchronized by default.

#### Optional Anki

Q: Which map is optimized for enum keys?
A: `EnumMap`.

</details>

<a id="col-map-007"></a>

<details>
<summary><strong>🧠 COL-MAP-007. What is `WeakHashMap`, and why is it not a general-purpose cache?</strong></summary>

#### Short answer

`WeakHashMap` stores weak keys, so entries can disappear when keys are no longer strongly reachable elsewhere.

#### Interview answer

It is useful for associating metadata with objects without preventing those key objects from being garbage-collected. It is not a general cache because eviction depends on GC reachability and timing, not on size, time, cost, hit rate or business policy.

#### Deep dive

Only keys are weak, not values. If a value strongly references its key, the entry may not be collectible as expected. Cleanup also happens through map operations and reference processing, so behavior can look non-deterministic.

#### Production angle

Use `WeakHashMap` for specialized object-associated metadata. For application caching, use a real cache library with explicit eviction, metrics and concurrency behavior.

#### Traps / caveats

- Entries can vanish at surprising times.
- Values can accidentally keep keys alive.
- It is not thread-safe by default.

#### Optional Anki

Q: Why is `WeakHashMap` not a normal cache?
A: Eviction is driven by GC reachability, not cache policy.

</details>

<a id="col-map-008"></a>

<details>
<summary><strong>🧠 COL-MAP-008. What is the difference between `keySet`, `values` and `entrySet` views?</strong></summary>

#### Short answer

`keySet()` views keys, `values()` views values, and `entrySet()` views key-value entries.

#### Interview answer

Use `keySet()` when only keys are needed, `values()` when only values are needed, and `entrySet()` when both key and value are needed. Iterating `entrySet()` is usually better than iterating keys and calling `get()` for every key.

#### Deep dive

The views are usually backed by the original map. Removing through a view removes from the map. Adding directly to most views is not supported because the map would not know the missing key or value.

#### Production angle

Choose `entrySet()` for efficient transformations and logging of mappings. It avoids unnecessary lookups and makes the code's intent clear.

#### Traps / caveats

- `values()` may contain duplicates.
- View removals affect the original map.
- Modifying the map during iteration can cause fail-fast behavior for non-concurrent maps.

#### Optional Anki

Q: Which view should you iterate when you need both key and value?
A: `entrySet()`.

</details>

<a id="col-map-009"></a>

<details>
<summary><strong>COL-MAP-009. What are `computeIfAbsent`, `merge` and `putIfAbsent` used for?</strong></summary>

#### Short answer

They simplify common conditional map updates such as lazy creation, counting and insert-if-missing.

#### Interview answer

`putIfAbsent` stores a value only if no value is mapped for the key. `computeIfAbsent` computes and stores a value only when needed, often for grouping or lazy initialization. `merge` combines a new value with an existing value, commonly for counters or aggregation.

#### Deep dive

Examples: `map.computeIfAbsent(key, k -> new ArrayList<>()).add(item)` for grouping, and `counts.merge(key, 1, Integer::sum)` for counting. In `ConcurrentHashMap`, these methods can provide atomic map-level updates, but mapping functions should be short and side-effect cautious.

#### Production angle

These methods reduce check-then-act bugs and duplicated code. In concurrent maps, they are preferable to manual `get` then `put` patterns.

#### Traps / caveats

- Mapping functions should not perform slow remote calls.
- Recursive updates to the same map can fail.
- `computeIfAbsent` behavior around null mappings differs by map and method contract.

#### Optional Anki

Q: Best simple method for frequency counting?
A: `map.merge(key, 1, Integer::sum)`.

</details>

<a id="col-map-010"></a>

<details>
<summary><strong>COL-MAP-010. What are common pitfalls when modifying a `Map` while iterating over it?</strong></summary>

#### Short answer

Modifying a non-concurrent map structurally outside the iterator can cause `ConcurrentModificationException` or skipped/undefined traversal behavior.

#### Interview answer

When iterating `entrySet()`, remove entries with the iterator's `remove()` method or use `removeIf()` on a supported view. Do not call `map.put()` or `map.remove()` during ordinary fail-fast iteration unless the API explicitly supports it.

#### Deep dive

Fail-fast iterators track structural modification counts on a best-effort basis. Concurrent maps behave differently: their iterators are weakly consistent and can tolerate concurrent updates, but they may or may not see all changes.

#### Production angle

This bug often appears in cleanup jobs, cache eviction code and filtering maps before returning DTOs. Prefer building a new map for transformations when clarity matters.

#### Traps / caveats

- `ConcurrentModificationException` can happen in one thread.
- Updating an existing value may not be structural for some maps.
- Concurrent map iteration has different visibility semantics.

#### Optional Anki

Q: Safe removal while iterating a normal map?
A: Use the iterator's `remove()` or a supported `removeIf()`.

</details>

<a id="col-map-011"></a>

<details>
<summary><strong>COL-MAP-011. When should a `Map` be replaced by a proper domain object?</strong></summary>

#### Short answer

When the keys represent fixed business fields or rules, a typed domain object is usually clearer and safer than a generic map.

#### Interview answer

Maps are good for dynamic key-value data. They are poor when code repeatedly uses string keys such as `"status"`, `"amount"` and `"currency"` to represent a known concept. A class or record gives named fields, validation, types and behavior.

#### Deep dive

Generic maps hide invariants. They allow missing keys, misspelled keys, wrong value types and unclear ownership. A domain object can enforce required fields, use value types and provide methods that express behavior.

#### Production angle

Map-heavy business code is hard to refactor and easy to break during API changes. Use maps at dynamic boundaries, then convert to typed models.

#### Traps / caveats

- `Map<String, Object>` often spreads unchecked casts.
- Stringly typed keys are not refactor-safe.
- A map does not document required fields well.

#### Optional Anki

Q: When is `Map<String, Object>` a smell?
A: When it represents a known business concept with fixed fields.

</details>

<a id="col-map-012"></a>

<details>
<summary><strong>COL-MAP-012. How can incorrect `equals()` or `hashCode()` break map behavior?</strong></summary>

#### Short answer

Maps may fail to find keys, store duplicate logical keys or overwrite unexpectedly if key equality is wrong or unstable.

#### Interview answer

`HashMap` uses key `hashCode()` to choose a bucket and `equals()` to find the exact key. If equal keys have different hash codes, lookup fails. If a key is mutated after insertion, it may be stored in the wrong bucket relative to its new state.

#### Deep dive

Sorted maps have a related issue with comparators. `TreeMap` uses comparison for key uniqueness. If comparison returns zero for two unequal keys, one mapping can replace the other.

#### Production angle

This is common with JPA entities, mutable DTOs, arrays as keys, Lombok equality over mutable fields and records containing mutable components.

#### Traps / caveats

- Equal keys must have equal hash codes.
- Do not mutate key fields used by equality.
- Comparator consistency matters for `TreeMap`.

#### Optional Anki

Q: What happens if a `HashMap` key's hash changes after insertion?
A: The entry may become unreachable by lookup.

</details>

<a id="col-map-013"></a>

<details>
<summary><strong>COL-MAP-013. How would you choose a `Map` implementation for a backend use case?</strong></summary>

#### Short answer

Choose by key semantics, ordering, lookup pattern, concurrency, memory behavior and whether a real cache or database lookup is more appropriate.

#### Interview answer

Use `HashMap` for ordinary in-memory lookup. Use `LinkedHashMap` for stable order or simple access-order behavior. Use `TreeMap` for sorted keys and range queries. Use `EnumMap` for enum keys. Use `ConcurrentHashMap` for shared concurrent access. Use a cache library when you need eviction, expiration, metrics or loading behavior.

#### Deep dive

The key design is as important as the implementation. Good keys are immutable, have stable equality and are not overly expensive to hash or compare. For large maps, consider memory overhead and whether the data should be indexed in a database instead.

#### Production angle

Map misuse often causes memory leaks in static maps, stale cache data, race conditions and per-request latency spikes from repeated resizing or large aggregations.

#### Traps / caveats

- A map is not automatically a cache.
- Thread-safe maps do not protect multi-map business invariants.
- Plain `HashMap` gives no stable output order.

#### Optional Anki

Q: Which map for enum keys?
A: `EnumMap`.

</details>
