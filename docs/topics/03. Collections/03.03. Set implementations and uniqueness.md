# 03.03. Set implementations and uniqueness

---

<a id="col-set-001"></a>

<details>
<summary><strong>COL-SET-001. What is a `Set`?</strong></summary>

#### Short answer

A `Set` is a collection that does not allow duplicate elements according to its equality or comparison rules.

#### Interview answer

`Set<E>` models membership and uniqueness. It answers questions like "have I seen this value?" or "which unique IDs are present?" Common implementations are `HashSet`, `LinkedHashSet`, `TreeSet`, `EnumSet` and concurrent or copy-on-write variants.

#### Deep dive

The definition of duplicate depends on implementation. Hash-based sets use `equals()` and `hashCode()`. Sorted sets such as `TreeSet` use comparison. This difference matters when comparison is inconsistent with `equals()`.

#### Production angle

Use sets for deduplication, membership checks, uniqueness validation and preventing repeated work. If database uniqueness matters, still enforce it in the database.

#### Traps / caveats

- A `Set` does not guarantee iteration order unless the implementation does.
- Mutable elements can break membership lookup.
- Set uniqueness is in-memory, not a database constraint.

#### Optional Anki

Q: What does `Set` primarily model?
A: Uniqueness and membership.

</details>

<a id="col-set-002"></a>

<details>
<summary><strong>COL-SET-002. What is the difference between `HashSet`, `LinkedHashSet` and `TreeSet`?</strong></summary>

#### Short answer

`HashSet` is hash-based and unordered, `LinkedHashSet` is hash-based with insertion order, and `TreeSet` is sorted by comparison.

#### Interview answer

Use `HashSet` for fast membership when order does not matter. Use `LinkedHashSet` when you need uniqueness plus predictable insertion order. Use `TreeSet` when you need sorted iteration or range queries such as lower, higher, floor, ceiling or subsets.

#### Deep dive

`HashSet` and `LinkedHashSet` use hash-based equality: `hashCode()` then `equals()`. `TreeSet` uses a tree and compares elements with natural ordering or a comparator. That means `TreeSet` can treat two objects as duplicates if `compare()` returns zero.

#### Production angle

Choosing between these often affects API output stability. If clients or tests expect stable order, avoid plain `HashSet`.

#### Traps / caveats

- Do not rely on `HashSet` iteration order.
- `TreeSet` requires comparable elements or a comparator.
- `LinkedHashSet` has extra memory overhead.

#### Optional Anki

Q: Which set supports sorted range operations?
A: `TreeSet`.

</details>

<a id="col-set-003"></a>

<details>
<summary><strong>COL-SET-003. How does `HashSet` work internally at a high level?</strong></summary>

#### Short answer

`HashSet` is backed by a hash table, effectively a `HashMap` where each set element is stored as a key.

#### Interview answer

When you add an element, `HashSet` uses its `hashCode()` to locate a bucket and `equals()` to check whether an equal element already exists. If not, it stores the element. This gives average constant-time add, remove and contains when hashes are well distributed.

#### Deep dive

Modern `HashMap` internals handle collisions with bucket chains and tree bins in heavy collision cases. The details belong more to `HashMap`, but the important set-level idea is that hash quality and stable equality drive correctness and performance.

#### Production angle

`HashSet` is excellent for de-duplicating IDs or checking membership. It fails badly when elements have broken or mutable equality.

#### Traps / caveats

- Equal objects must have equal hash codes.
- Mutating fields used by `equals()` or `hashCode()` breaks lookup.
- Very poor hash distribution hurts performance.

#### Optional Anki

Q: What backs a `HashSet`?
A: A hash table, implemented through `HashMap`-style keys.

</details>

<a id="col-set-004"></a>

<details>
<summary><strong>COL-SET-004. Why does `HashSet` rely on `equals()` and `hashCode()`?</strong></summary>

#### Short answer

Because it needs `hashCode()` to find candidate storage locations and `equals()` to decide logical uniqueness.

#### Interview answer

`hashCode()` narrows the search to a bucket. `equals()` decides whether an existing element is the same logical value. If two equal objects have different hash codes, the set may store both or fail to find an existing value.

#### Deep dive

The contract is one-way: if `a.equals(b)` is true, then `a.hashCode() == b.hashCode()` must be true. The reverse is not required because collisions can happen. `HashSet` must still compare with `equals()` inside a bucket.

#### Production angle

This is common with DTOs, records with mutable components, Lombok-generated equality over wrong fields, and JPA entities whose IDs change after persistence.

#### Traps / caveats

- Same hash code does not imply equality.
- Do not include mutable fields in hash-based identity.
- Arrays use identity equality unless handled specially.

#### Optional Anki

Q: What must be true if two objects are equal?
A: They must have the same `hashCode()`.

</details>

<a id="col-set-005"></a>

<details>
<summary><strong>COL-SET-005. What is `LinkedHashSet`, and when would you use it?</strong></summary>

#### Short answer

`LinkedHashSet` is a hash set that preserves insertion order during iteration.

#### Interview answer

It combines hash-based uniqueness with predictable iteration order. Use it when you want to remove duplicates but keep the first-seen order, for example ordered request IDs, stable API responses or preserving user-provided order after validation.

#### Deep dive

Internally it maintains links between entries in addition to hash table storage. That gives stable insertion-order iteration at the cost of extra memory. Membership checks remain average `O(1)`.

#### Production angle

`LinkedHashSet` is a good default for deduplication when output order matters. It avoids flaky tests and surprising response ordering caused by plain `HashSet`.

#### Traps / caveats

- It is not sorted.
- It has more memory overhead than `HashSet`.
- It is not thread-safe by default.

#### Optional Anki

Q: How do you deduplicate while preserving insertion order?
A: Use `LinkedHashSet`.

</details>

<a id="col-set-006"></a>

<details>
<summary><strong>🧠 COL-SET-006. What are `SortedSet`, `NavigableSet` and `TreeSet`?</strong></summary>

#### Short answer

`SortedSet` represents sorted unique elements, `NavigableSet` adds navigation operations, and `TreeSet` is the common tree-based implementation.

#### Interview answer

`SortedSet` exposes sorted iteration and range views. `NavigableSet` adds operations such as `lower`, `floor`, `ceiling`, `higher`, `pollFirst` and `pollLast`. `TreeSet` implements these contracts using natural ordering or a comparator.

#### Deep dive

`TreeSet` operations are typically `O(log n)`. Unlike `HashSet`, it does not use `hashCode()` for membership. It uses comparison. This makes it useful for range logic and ordered lookups.

#### Production angle

Use it for things like sorted thresholds, time windows, ordered codes or nearest-value lookup. Do not choose it just because "sorted looks nice" if a database query or API sort is the real source of order.

#### Traps / caveats

- Elements must be mutually comparable.
- Comparator bugs can corrupt set semantics.
- It costs more per basic lookup than `HashSet`.

#### Optional Anki

Q: What does `NavigableSet` add?
A: Nearest-match and range/navigation operations.

</details>

<a id="col-set-007"></a>

<details>
<summary><strong>🧠 COL-SET-007. How does `TreeSet` use `Comparable` or `Comparator`?</strong></summary>

#### Short answer

`TreeSet` orders and identifies duplicates by comparing elements with natural ordering or a supplied comparator.

#### Interview answer

If no comparator is provided, elements must implement `Comparable`. If a comparator is provided, `TreeSet` uses it for all ordering and uniqueness decisions. If comparison returns zero, the set treats the elements as duplicates.

#### Deep dive

The comparator must be consistent and transitive. If `a < b` and `b < c`, then `a < c` should hold. Broken comparators can lead to missing elements, strange ordering or operations that appear inconsistent.

#### Production angle

Comparator code often lives in service-layer sorting, reporting and deduplication. It deserves tests for equal values, nulls, ties and reversed order.

#### Traps / caveats

- `compareTo()` returning zero means duplicate to `TreeSet`.
- Natural ordering can differ from `equals()`.
- Null handling depends on the comparator and implementation rules.

#### Optional Anki

Q: Does `TreeSet` use `hashCode()` for uniqueness?
A: No. It uses comparison.

</details>

<a id="col-set-008"></a>

<details>
<summary><strong>COL-SET-008. What happens if a `TreeSet` comparator is inconsistent with `equals()`?</strong></summary>

#### Short answer

The set may treat unequal objects as duplicates or equal objects as distinct according to comparison, not `equals()`.

#### Interview answer

If the comparator returns zero for two objects, `TreeSet` considers them the same element. For example, comparing users only by email means two user objects with the same email cannot both be stored, even if `equals()` compares IDs and says they differ.

#### Deep dive

This is legal but dangerous unless intentional. Sorted sets define uniqueness through ordering. If ordering is inconsistent with equality, collection behavior can surprise callers who expect ordinary `equals()` semantics.

#### Production angle

This appears in deduplication, report generation and sorting by business keys. If the comparator defines a business uniqueness rule, document it. Otherwise include tie-breakers to avoid accidental drops.

#### Traps / caveats

- `TreeSet.size()` can be smaller than expected.
- A comparator used for display sorting may be wrong for uniqueness.
- BigDecimal is a classic equality-vs-comparison trap.

#### Optional Anki

Q: What does `compare(a, b) == 0` mean to `TreeSet`?
A: The set treats `a` and `b` as duplicates.

</details>

<a id="col-set-009"></a>

<details>
<summary><strong>🧠 COL-SET-009. What is `EnumSet`, and why is it efficient?</strong></summary>

#### Short answer

`EnumSet` is a specialized set for enum values, usually represented compactly with bits.

#### Interview answer

Because enum constants have a fixed finite universe and stable ordinal positions, `EnumSet` can represent membership very compactly and perform operations quickly. It is often better than `HashSet<EnumType>` for sets of enum flags or states.

#### Deep dive

`EnumSet` is type-safe and supports bulk operations such as complement, range and all-of. It does not store arbitrary objects and cannot contain null. Its implementation details vary by enum size, but the mental model is a bit vector.

#### Production angle

Use it for permissions, feature flags inside a process, allowed statuses or supported modes when the set elements are enum constants.

#### Traps / caveats

- It only works for one enum type.
- Do not persist enum ordinals as business data.
- It is not synchronized by default.

#### Optional Anki

Q: Why is `EnumSet` compact?
A: Enum membership can be represented by bits over a fixed enum universe.

</details>

<a id="col-set-010"></a>

<details>
<summary><strong>🧠 COL-SET-010. What is `CopyOnWriteArraySet`, and when is it useful?</strong></summary>

#### Short answer

`CopyOnWriteArraySet` is a thread-safe set backed by copy-on-write array behavior, useful for small read-mostly sets.

#### Interview answer

It is built on `CopyOnWriteArrayList` semantics: reads are snapshot-like and do not block, while writes copy the underlying array. This makes iteration safe without explicit locks, but mutation is expensive.

#### Deep dive

It is useful when reads and iteration dominate writes, for example listener registries, subscribers or feature callbacks. It is a poor choice for large sets or frequently changing data.

#### Production angle

It can simplify concurrency for small read-mostly collections. In write-heavy paths it creates allocation pressure and latency.

#### Traps / caveats

- Every write copies the backing array.
- Snapshot iteration may not see recent writes.
- It is not a general replacement for `ConcurrentHashMap.newKeySet()`.

#### Optional Anki

Q: When is copy-on-write appropriate?
A: Small collections with many reads and rare writes.

</details>

<a id="col-set-011"></a>

<details>
<summary><strong>COL-SET-011. What is the difference between Java `Set` uniqueness and database uniqueness?</strong></summary>

#### Short answer

Java `Set` uniqueness is in-memory and based on Java equality rules; database uniqueness is persistent and enforced by database constraints.

#### Interview answer

A `Set` can prevent duplicates inside one JVM object at one point in time. It cannot protect against concurrent requests, other service instances, direct database writes or transaction races. Database unique constraints are the source of truth for persisted uniqueness.

#### Deep dive

Java equality may also differ from database equality. Case sensitivity, collation, trimming, null handling and normalized values can differ. For example, a database unique index on lowercased email is not the same as a `HashSet<String>` unless the Java code normalizes the same way.

#### Production angle

Use sets for early validation and better error messages, but enforce critical uniqueness in the database. Handle duplicate-key errors gracefully.

#### Traps / caveats

- In-memory checks have race conditions.
- Java and database comparison rules can differ.
- A distributed system has many JVMs, not one set.

#### Optional Anki

Q: Can a Java `Set` replace a database unique constraint?
A: No.

</details>

<a id="col-set-012"></a>

<details>
<summary><strong>COL-SET-012. How would you remove duplicates while preserving insertion order?</strong></summary>

#### Short answer

Use `LinkedHashSet`, then convert back to a list if a list result is needed.

#### Interview answer

For example, `new ArrayList<>(new LinkedHashSet<>(input))` removes duplicates and keeps the first occurrence order. `LinkedHashSet` uses hash-based uniqueness while maintaining insertion order.

#### Deep dive

This assumes element equality is correct. If uniqueness is based on a field, such as user email, you may need a `Map` keyed by that field or a stream collector with a merge rule.

#### Production angle

This is useful for request IDs, preserving user-provided order or stable API output. For large inputs, consider memory use and whether deduplication belongs in SQL.

#### Traps / caveats

- It keeps the first occurrence, not the last.
- Equality must match the business rule.
- It is still an in-memory operation.

#### Optional Anki

Q: Which set removes duplicates and preserves insertion order?
A: `LinkedHashSet`.

</details>

<a id="col-set-013"></a>

<details>
<summary><strong>COL-SET-013. What are common mistakes when storing mutable objects in a `Set`?</strong></summary>

#### Short answer

Mutating fields used by equality or comparison after insertion can make elements unreachable or corrupt set semantics.

#### Interview answer

In a `HashSet`, if an element's `hashCode()` changes after insertion, the set may look in the wrong bucket and fail to find it. In a `TreeSet`, if fields used by the comparator change, the tree order may no longer be valid.

#### Deep dive

This is especially risky for entities, DTOs with setters, records containing mutable components, arrays and collections used inside equality. Prefer immutable value objects for set elements, or remove and re-add after mutation if mutation is unavoidable.

#### Production angle

Symptoms include duplicate logical values, failed removals, missing elements and inconsistent validation. These bugs are hard to diagnose because the object is "visibly" in the set during debugging.

#### Traps / caveats

- `final` reference fields do not make contained objects immutable.
- JPA entity equality can change around persistence.
- Comparator-based sets have the same mutation risk.

#### Optional Anki

Q: Why is mutating a `HashSet` element dangerous?
A: It can change `hashCode()` or equality and make lookup fail.

</details>

<a id="col-set-014"></a>

<details>
<summary><strong>COL-SET-014. How would you choose between `HashSet`, `LinkedHashSet` and `TreeSet`?</strong></summary>

#### Short answer

Use `HashSet` for fastest ordinary membership, `LinkedHashSet` for membership plus stable insertion order, and `TreeSet` for sorted/range operations.

#### Interview answer

Start with semantics. If order does not matter, `HashSet` is usually best. If first-seen order matters, use `LinkedHashSet`. If you need sorted iteration, nearest-match lookups or range views, use `TreeSet`.

#### Deep dive

Then consider costs. `HashSet` gives average `O(1)` operations. `LinkedHashSet` adds memory overhead for links. `TreeSet` gives `O(log n)` operations and requires reliable comparison.

#### Production angle

Pick the collection that documents intent. If an API response must be ordered, plain `HashSet` is a bug waiting to happen. If uniqueness must be persistent, add a database constraint too.

#### Traps / caveats

- Do not use `TreeSet` just to get stable order if insertion order is required.
- Do not rely on `HashSet` order in tests.
- Check element equality or comparator correctness.

#### Optional Anki

Q: Which set for uniqueness plus first-seen order?
A: `LinkedHashSet`.

</details>
