# Java backend integration: JDBC, pools and transactions

<a id="db-java-001"></a>

<details>
<summary><strong>DB-JAVA-001. What is JDBC?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>JDBC is the standard Java API for connecting to relational databases and executing SQL.</p>
</td>
<td valign="top" width="50%">
<p>JDBC — стандартный Java API для подключения к relational databases и выполнения SQL.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>JDBC provides interfaces like <code>Connection</code>, <code>Statement</code>, <code>PreparedStatement</code>, <code>CallableStatement</code>, and <code>ResultSet</code>.</p>
<p>Most higher-level tools such as Spring JDBC, JPA providers, and migration tools ultimately use JDBC drivers underneath.</p>
</td>
<td valign="top" width="50%">
<p>JDBC предоставляет interfaces вроде <code>Connection</code>, <code>Statement</code>, <code>PreparedStatement</code>, <code>CallableStatement</code> и <code>ResultSet</code>.</p>
<p>Большинство higher-level tools, таких как Spring JDBC, JPA providers и migration tools, в итоге используют JDBC drivers под капотом.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>JDBC is driver-based. The PostgreSQL JDBC driver implements the JDBC interfaces and speaks PostgreSQL protocol.</p>
<p>JDBC itself is low-level: it does not manage ORM mappings, transactions at service level, or connection pooling by magic.</p>
</td>
<td valign="top" width="50%">
<p>JDBC основан на drivers. PostgreSQL JDBC driver implements JDBC interfaces и говорит по PostgreSQL protocol.</p>
<p>Сам JDBC low-level: он не управляет ORM mappings, service-level transactions или connection pooling автоматически.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>For senior backend work, JDBC knowledge helps debug connection leaks, transaction boundaries, parameter binding, batch operations, and generated SQL behavior.</p>
<p>Even if using JPA, production incidents often require JDBC-level understanding.</p>
</td>
<td valign="top" width="50%">
<p>Для senior backend знание JDBC помогает debug connection leaks, transaction boundaries, parameter binding, batch operations и generated SQL behavior.</p>
<p>Даже при использовании JPA production инциденты часто требуют JDBC-level understanding.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul>
<li>JDBC is not an ORM.</li>
<li>Always close resources or use try-with-resources / framework management.</li>
<li>Connections are expensive and should usually come from a pool.</li>
<li>Driver behavior can affect performance.</li>
</ul>
</td>
<td valign="top" width="50%">
<ul>
<li>JDBC — не ORM.</li>
<li>Всегда закрывай resources или используй try-with-resources/framework management.</li>
<li>Connections дорогие и обычно должны приходить из pool.</li>
<li>Driver behavior может влиять на performance.</li>
</ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: What is JDBC?<br>A: The standard Java API for database connectivity and SQL execution.</p>
</td>
<td valign="top" width="50%">
<p>Q: Что такое JDBC?<br>A: Стандартный Java API для подключения к БД и выполнения SQL.</p>
</td>
</tr>
</tbody>
</table>

<summary><strong>🧠 DB-JAVA-002. What is a JDBC URL?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>A JDBC URL is a connection string that tells the JDBC driver which database to connect to and with what parameters.</p>
</td>
<td valign="top" width="50%">
<p>JDBC URL — connection string, который говорит JDBC driver, к какой БД подключаться и с какими параметрами.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>For PostgreSQL it often looks like <code>jdbc:postgresql://host:5432/dbname</code>. It may include SSL, timeouts, application name, and other driver options.</p>
<p>The URL format is driver-specific.</p>
</td>
<td valign="top" width="50%">
<p>Для PostgreSQL он часто выглядит как <code>jdbc:postgresql://host:5432/dbname</code>. Он может включать SSL, timeouts, application name и другие driver options.</p>
<p>Формат URL зависит от driver.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>A JDBC URL is usually used together with username/password or other authentication methods. In production, secrets should come from secure configuration, not hardcoded strings.</p>
<p>Some options can also be configured through DataSource properties.</p>
</td>
<td valign="top" width="50%">
<p>JDBC URL обычно используется вместе с username/password или другими auth methods. В production секреты должны приходить из secure configuration, а не hardcoded strings.</p>
<p>Некоторые options также можно настроить через DataSource properties.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Use connection names/application names to identify services in <code>pg_stat_activity</code>. Configure SSL and timeouts deliberately.</p>
<p>Bad URL/configuration can cause hidden production issues, such as missing timeouts or wrong target database.</p>
</td>
<td valign="top" width="50%">
<p>Используй connection names/application names, чтобы видеть services в <code>pg_stat_activity</code>. SSL и timeouts нужно настраивать осознанно.</p>
<p>Плохой URL/configuration может создать hidden production issues: missing timeouts или wrong target database.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul>
<li>Do not log credentials.</li>
<li>Different environments must not accidentally point to production.</li>
<li>Driver parameters differ by database.</li>
<li>Timeout defaults may be unsafe.</li>
</ul>
</td>
<td valign="top" width="50%">
<ul>
<li>Не логируй credentials.</li>
<li>Разные environments не должны случайно указывать на production.</li>
<li>Driver parameters отличаются по DB.</li>
<li>Timeout defaults могут быть unsafe.</li>
</ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: What is a JDBC URL for?<br>A: To identify the database endpoint and connection options for the driver.</p>
</td>
<td valign="top" width="50%">
<p>Q: Для чего нужен JDBC URL?<br>A: Чтобы указать database endpoint и connection options для driver.</p>
</td>
</tr>

<details>
<summary><strong>DB-JAVA-003. What is DataSource?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>A DataSource is a factory for database connections, commonly backed by a connection pool in server applications.</p>
</td>
<td valign="top" width="50%">
<p>DataSource — factory для database connections, часто backed by пул соединений (connection pool) в server applications.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>In modern Java apps, code usually obtains connections from <code>DataSource</code> instead of <code>DriverManager</code>. Frameworks like Spring manage the DataSource and inject it where needed.</p>
<p>A DataSource can provide pooling, configuration, monitoring, and integration with transactions.</p>
</td>
<td valign="top" width="50%">
<p>В modern Java apps connections обычно получают из <code>DataSource</code>, а не <code>DriverManager</code>. Frameworks вроде Spring manage DataSource и inject его.</p>
<p>DataSource может предоставлять pooling, configuration, monitoring и integration with transactions.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>DataSource is an interface; implementations include HikariCP, Tomcat JDBC Pool, application server pools, and vendor-specific sources.</p>
<p>The application code should not usually create a new physical database connection per request.</p>
</td>
<td valign="top" width="50%">
<p>DataSource — interface; implementations включают HikariCP, Tomcat JDBC Pool, application server pools и vendor-specific sources.</p>
<p>Application code обычно не должен создавать новый physical database connection на request.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>In production, tune the DataSource/pool: maximum pool size, connection timeout, idle timeout, max lifetime, leak detection, validation query/keepalive.</p>
<p>Expose pool metrics.</p>
</td>
<td valign="top" width="50%">
<p>В production нужно tune DataSource/pool: maximum pool size, connection timeout, idle timeout, max lifetime, утечь detection, validation query/keepalive.</p>
<p>Нужно expose метрики пула.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul>
<li>DataSource does not automatically make bad queries fast.</li>
<li>Pool sizing must match DB capacity.</li>
<li>A misconfigured pool can overload PostgreSQL.</li>
<li>Do not bypass the framework's transaction-aware DataSource.</li>
</ul>
</td>
<td valign="top" width="50%">
<ul>
<li>DataSource не делает плохие запросы быстрыми.</li>
<li>Pool sizing должен соответствовать DB capacity.</li>
<li>Misconfigured pool может overload PostgreSQL.</li>
<li>Не обходи framework transaction-aware DataSource.</li>
</ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: What is DataSource?<br>A: A configurable source/factory of database connections, often with pooling.</p>
</td>
<td valign="top" width="50%">
<p>Q: Что такое DataSource?<br>A: Configurable source/factory database connections, часто с pooling.</p>
</td>
</tr>

<details>
<summary><strong>DB-JAVA-004. What is the difference between DriverManager and DataSource?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>DriverManager is a simple static API for creating connections; DataSource is configurable, injectable, and usually supports pooling.</p>
</td>
<td valign="top" width="50%">
<p>DriverManager — простой static API для создания connections; DataSource configurable, injectable и обычно поддерживает pooling.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p><code>DriverManager.getConnection()</code> is fine for small examples and tools. Server applications should use DataSource because it integrates better with frameworks, pools, JNDI, metrics, and transaction managers.</p>
<p>DataSource separates connection configuration from application logic.</p>
</td>
<td valign="top" width="50%">
<p><code>DriverManager.getConnection()</code> подходит для маленьких examples и tools. Server applications должны использовать DataSource, потому что он лучше интегрируется с frameworks, pools, JNDI, metrics и transaction managers.</p>
<p>DataSource отделяет connection configuration от application logic.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>DriverManager usually creates a physical connection when called. A pooled DataSource returns a logical handle to an existing pooled connection.</p>
<p>Spring's transaction management also expects to work with a managed DataSource.</p>
</td>
<td valign="top" width="50%">
<p>DriverManager обычно создает physical connection при вызове. Pooled DataSource возвращает logical handle к existing pooled connection.</p>
<p>Spring управление транзакциями также ожидает managed DataSource.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>In production, use DataSource. Direct DriverManager calls inside business code can bypass pooling and transaction management.</p>
<p>That can cause slow requests, too many DB connections, or inconsistent transactions.</p>
</td>
<td valign="top" width="50%">
<p>В production используй DataSource. Прямые вызовы DriverManager внутри бизнес-код могут bypass pooling и управление транзакциями.</p>
<p>Это может вызвать медленные запросы приложения, слишком много соединений с БД или неконсистентные транзакции.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul>
<li>DriverManager is not appropriate for high-throughput services.</li>
<li>DataSource still needs correct pooling config.</li>
<li>Mixing connection sources can break transactions.</li>
<li>Direct connections are easy to leak.</li>
</ul>
</td>
<td valign="top" width="50%">
<ul>
<li>DriverManager не подходит для high-throughput services.</li>
<li>DataSource всё равно требует правильной pool config.</li>
<li>Mixing connection sources может break transactions.</li>
<li>Прямые соединения легко утечь.</li>
</ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: DriverManager vs DataSource?<br>A: DriverManager creates direct connections; DataSource is managed/configurable and commonly pooled.</p>
</td>
<td valign="top" width="50%">
<p>Q: DriverManager vs DataSource?<br>A: DriverManager создаёт direct connections; DataSource managed/configurable и обычно pooled.</p>
</td>
</tr>

<summary><strong>DB-JAVA-005. What is Statement?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Statement is a JDBC object used to execute static SQL text without parameter binding.</p>
</td>
<td valign="top" width="50%">
<p>Statement — JDBC object для выполнения static SQL text без parameter binding.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p><code>Statement</code> can execute SQL strings, but values are usually concatenated into SQL manually. That makes it dangerous for user input.</p>
<p>For dynamic values, use <code>PreparedStatement</code>.</p>
</td>
<td valign="top" width="50%">
<p><code>Statement</code> может выполнять SQL strings, но values обычно concatenated вручную. Это опасно для user input.</p>
<p>Для dynamic values используй <code>PreparedStatement</code>.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Statement has methods like <code>executeQuery</code>, <code>executeUpdate</code>, and <code>execute</code>. It is useful for fixed admin queries or DDL scripts generated safely.</p>
<p>It does not separate SQL structure from parameters.</p>
</td>
<td valign="top" width="50%">
<p>Statement имеет методы <code>executeQuery</code>, <code>executeUpdate</code> и <code>execute</code>. Он полезен для фиксированных административных запросов или безопасно сгенерированных DDL-скриптов.</p>
<p>Он не отделяет SQL structure от parameters.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>In production application code, raw Statement should be rare. It is easy to introduce SQL injection or quoting bugs.</p>
<p>If identifiers must be dynamic, use allowlists and safe query builders.</p>
</td>
<td valign="top" width="50%">
<p>В production application code raw Statement должен быть редким. Легко получить SQL-инъекция (SQL injection) или quoting bugs.</p>
<p>Если identifiers dynamic, нужны allowlists и safe query builders.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul>
<li>Never concatenate user input into Statement SQL.</li>
<li>PreparedStatement is the default choice for values.</li>
<li>Statement can still be useful for fixed SQL.</li>
<li>Dynamic identifiers need allowlists, not bind parameters.</li>
</ul>
</td>
<td valign="top" width="50%">
<ul>
<li>Никогда не concatenate user input в Statement SQL.</li>
<li>PreparedStatement — default choice для values.</li>
<li>Statement может быть полезен для fixed SQL.</li>
<li>Dynamic identifiers требуют allowlists, а не bind parameters.</li>
</ul>
</td>

<th colspan="2" align="left">Optional Anki</th>

<td valign="top" width="50%">

<summary><strong>DB-JAVA-006. What is PreparedStatement?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>PreparedStatement is a JDBC statement with parameter placeholders that lets values be bound separately from SQL text.</p>
</td>
<td valign="top" width="50%">
<p>PreparedStatement — JDBC statement с parameter placeholders, позволяющий bind values отдельно от SQL text.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Instead of concatenating values into SQL, we write placeholders and bind values through methods like <code>setString</code>, <code>setLong</code>, and <code>setTimestamp</code>.</p>
<p>This improves safety and can help performance for repeated statements.</p>
</td>
<td valign="top" width="50%">
<p>Вместо concatenating values в SQL, мы пишем placeholders и bind values через методы <code>setString</code>, <code>setLong</code>, <code>setTimestamp</code>.</p>
<p>Это повышает safety и может помочь performance для repeated statements.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>A prepared statement separates SQL code from data values. The database/driver treats bound parameters as values, not executable SQL.</p>
<p>Depending on driver and DB, it may be server-side prepared or emulated client-side until a threshold.</p>
</td>
<td valign="top" width="50%">
<p>Prepared statement отделяет SQL code от data values. Database/driver treats bound parameters as values, not executable SQL.</p>
<p>В зависимости от driver и DB он может быть server-side prepared или client-side emulated до threshold.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Use PreparedStatement by default for application SQL. It is central for SQL injection prevention and correct type handling.</p>
<p>Still design query shape carefully; parameters cannot safely replace identifiers like table or column names.</p>
</td>
<td valign="top" width="50%">
<p>Используй PreparedStatement по умолчанию для application SQL. Он важен для prevention SQL-инъекция (SQL injection) и correct type handling.</p>
<p>Но форма запроса всё равно нужно проектировать; parameters не заменяют safely identifiers вроде table или column names.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Traps / caveats</th>
</tr>
<tr>
<td valign="top" width="50%">
<ul>
<li>PreparedStatement prevents value injection, not bad authorization.</li>
<li>It does not parameterize column/table names.</li>
<li>Generic prepared plans can sometimes hurt performance.</li>
<li>Always bind values with correct types.</li>
</ul>
</td>
<td valign="top" width="50%">
<ul>
<li>PreparedStatement предотвращает value injection, но не плохую authorization.</li>
<li>Он не parameterize column/table names.</li>
<li>Generic prepared plans иногда вредят performance.</li>
<li>Bind values with correct types.</li>
</ul>
</td>
</tr>
<tr>
<th colspan="2" align="left">Optional Anki</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>Q: What is PreparedStatement?<br>A: A parameterized JDBC statement that binds values separately from SQL text.</p>
</td>
<td valign="top" width="50%">
<p>Q: Что такое PreparedStatement?<br>A: Parameterized JDBC statement, который bind values отдельно от SQL text.</p>

<details>
<summary><strong>DB-JAVA-007. How does PreparedStatement help prevent SQL injection?</strong></summary>

<table>
<tbody>
<tr>
<th colspan="2" align="left">Short answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>It sends SQL structure and parameter values separately, so user input is treated as data rather than SQL code.</p>
</td>
<td valign="top" width="50%">
<p>Он отправляет SQL structure и значения параметров отдельно, поэтому user input трактуется как data, а не SQL code.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Interview answer</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>If a user enters <code>' OR 1=1 --</code>, a prepared statement binds it as a string value, not as SQL syntax.</p>
<p>This prevents the classic attack where input breaks out of quotes and changes the query.</p>
</td>
<td valign="top" width="50%">
<p>Если user вводит <code>' OR 1=1 --</code>, prepared statement bind-ит это как string value, а не SQL syntax.</p>
<p>Это предотвращает classic attack, где input выходит из quotes и меняет query.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Deep dive</th>
</tr>
<tr>
<td valign="top" width="50%">
<p>PreparedStatement is effective for values in predicates, inserts and updates. It does not automatically secure dynamic identifiers, dynamically assembled SQL fragments, or unsafe ORDER BY clauses.</p>
<p>Safe dynamic SQL still needs allowlists.</p>
</td>
<td valign="top" width="50%">
<p>PreparedStatement эффективен для values в predicates, inserts и updates. Он не защищает автоматически динамические идентификаторы, dynamically assembled SQL fragments или unsafe ORDER BY.</p>
<p>Safe dynamic SQL всё равно требует allowlists.</p>
</td>
</tr>
<tr>
<th colspan="2" align="left">Production angle</th>
</tr>
